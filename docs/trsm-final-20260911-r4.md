## KML 环境区别

官方指定 `/home/HPC/HPCKit/latest/modulefiles` 路径缺失，默认 `kblas.h` 编译和 `-lkblas` 链接仍失败。此次扩大目录搜索后，发现 `/opt/donaudata/donau/HPCKit_25.1.0_Linux-aarch64/package/KunpengHPCKit-kml.25.1.0` 下实际存在 KML 25.1 头文件和 GCC 多线程动态库。

该包仍是解包布局 `gcclib/`，模块文件按安装布局 `lib/` 生成，不能直接套用旧的模块路径。后续通过 CPATH、LIBRARY_PATH、LD_LIBRARY_PATH 指向实际头文件和库，取消 KBLAS_LIB 覆盖，保留原 run.sh 默认 -lkblas。同一 ZIP 的 **KML 25.1 + GCC 12.3.1 独立解压复跑已完成，三轮 9/9 PASS**（作业1528027）；它不能等同比赛指定的 KML 25.2.0 复验。详见[KML环境排查与独立验证](trsm-kml251-20260911.md)。上面的优化对照与包级成绩均是 OpenBLAS 环境。

KML准备阶段保留了两次失败：1525204空NUMA CPU列表解析失败；1525797系统GCC10的OpenMP运行库缺符号导致链接失败。最终1528027在私有作业目录解压超算已有GCC12.3.1后完成验证，未做系统安装。

## 使用

解压进入 trsm/，仅在调度分配的鲲鹏单 NUMA 38 核环境运行。比赛指定环境按包内 README 设置：`unset KBLAS_LIB`、`OMP_NUM_THREADS=38 OMP_DYNAMIC=FALSE CPU_TARGET=generic TEST_RUNS=3`，然后 `bash run.sh`。包中无二进制、参考库或账户配置。
