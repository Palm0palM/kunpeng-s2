# TRSM 第十二轮：4×32 核的 CT 分块比较

本轮 **不晋级，保持 T8-svepanel16 和现有提交包**。T13 的大用例较 T8 快 **7.15%**，三组中位数合计快 **4.55%**，仍未超过 **5.26%** 波动门槛；CT128、CT32 的大用例均慢于原 CT64。作业 **1579645 SUCCEEDED**，调度和进程退出成功，36/36 正式结果、12/12 预热及全部预检通过，最大官方误差1.11e-15。

四成员为 A=T8-control12-repeat-r12、B=T13-sve4x32-repeat-r12、C=T15-svetile128、D=T16-svetile32。A/B 是既有版本的新运行，分别保留 r11 作业1579600的完整 prior 记录；C/D 从 T13 复制，仅把大路径 CT 常量64改为128或32，KB仍为256，核、打包、算术顺序、barrier、尾部、回退及小工作集路径不变。三个候选的晋级父基线都为 T8-control12；T13同时作为分块改动的对照，不重新定义为已晋级父版本。

同一计算节点、NUMA3、CPU114–151，38线程、24GiB、1800秒上限，实际运行约381秒。环境为 Huawei KML25.1.0 真实头文件和默认-lkblas、GCC12.3.1及其私有libgomp，每套实际依赖检查通过，无OpenBLAS。**不是指定 KML25.2.0 复验**；不与不同节点分配或历史OpenBLAS/GCC10作业合并成绩。官方输入、runner、benchmark、计时区和1e-12精度保持不变。

合计是逐用例中位数之和，仅为内部指标，不是官方分数。没有候选的逐用例中位数较T8退步超过1%，但三者合计改善均低于各自波动门槛。前三轮T13大用例的改善方向一致，但各轮仍独立判断，不合并样本或放宽门槛。

相对本轮 T13，CT128 大用例慢 **4.75%**、合计慢 **3.04%**；CT32 大用例慢 **2.22%**、合计慢 **0.81%**。小工作集的前两组没有对应源码改动，计时差异不能归因为 CT 或宽核优化。CT同控行列任务块，增加CT会减少任务数；本轮结果支持继续保留CT64，不凭任务数推断缓存行为或性能原因。

通用预检每成员通过14组直接核、406组整算子和28组空操作。T13/T15/T16各通过28组直接4×32核与28组整算子，覆盖31/32/33、63/64/65、95/96/97、127/128/129列，行尾、1/4/38线程、共享分配失败、无SVE和实际16字节窄VL。各成员56个参数检查用例、463420次参数观察、0不符；七个测试进程均记录正确KB256及其CT64/128/32。L只读、B保护区及原精度检查通过。测试副本插桩未进入官方计时或原源码目标汇编，没有运行服务器sanitizer。

三种CT在计算节点从原源码生成的4×32函数汇编相同：每k热循环34条指令，其中16条FMA，全函数没有栈访问或内部调用。这个观察表明微核本身没有变化，不能据此预测调度改动的整体速度。[独立日志与汇编审查](../records/evidence/trsm-stage-r12-20260912/cohorts/compare/assembly-review-tile.md)保留实际命令来源和计数。

记录与源码留在[完整公开归档](../records/evidence/trsm-stage-r12-20260912/README.md)，包括冻结提交脚本、三个CT的实际预检与汇编、逐套日志、环境和两份prior。[验证审计](../records/evidence/trsm-stage-r12-20260912/cohorts/compare/actual-run-audit.json)及[结果汇总](../records/evidence/trsm-stage-r12-20260912/cohorts/compare/result.json)可追溯本轮；CT相对T13的机器可读比较单独标为机理对照，不作为更换晋级父版本的依据。公开副本脱敏，原件保留在本地独立目录。

下一步准备比较 T8、T10 和仅改变共享L生产循环静态调度的T14。中用例使用的小工作集路径不受CT改动影响；T14的目标是减少该生产循环工作量不均，复制总量和消费者调度仍不变。T10此前中用例退化，现有日志不能证明损失主要来自生产不均，因此必须保留T10同期对照与T8晋级比较，不能预判修复成功。T14尚未测试。
