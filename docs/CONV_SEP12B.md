# CONV 2026-09-12 新一轮：C28 / C29 / C30

**正式最佳仍为 C6 = C26-r1，源码来源 C26-row4loads。** C6 已在提交 [b5ef7ea](https://github.com/Palm0palM/kunpeng-s2/commit/b5ef7ea27958b1531feadf3cc50f66a23c3a02f4) 发布，可直接使用该提交下的 [C6 原包](https://github.com/Palm0palM/kunpeng-s2/blob/b5ef7ea27958b1531feadf3cc50f66a23c3a02f4/conv/result/C6/conv.zip)。首组性能已经回收，三个候选均未达到预先声明的晋级门槛；不晋级 C7，不替换 C6 提交包。

三份候选专项均已通过：C28 作业 **1576127** 为 **108,888 项**，C29 作业 **1579242** 为 **121,560 项**，C30 作业 **1579257** 为 **131,064 项**，合计 **361,512 项全部通过**。C29 的两个累加器溢出属于性能观察，不影响已经通过的正确性结论。五成员性能对照作业 **1579274 已完整回收**，15套件、60/60 PASS、最大误差0。相对预先指定的关闭 C6 控制，C28 耗时增加0.86%，C29增加8.22%；C30减少1.04%，但未超过关闭控制2.02%的波动门槛。三个候选均 eligible=false，正式最佳不变。

所有编译、正确性、专项和性能工作均在调度分配的超算计算节点执行。本机只进行轻量编辑、传输和记录整理。已验证结果与准备状态分别记录，未完成的检查不计入通过数量。

## 候选策略与改动范围

| 候选 | 源码来源 | 单一假设及改动 | 主要风险 |
| --- | --- | --- | --- |
| [C28-row4x6u1](../records/experiments/conv/C28-row4x6u1.json) | C24-row4x4 | 只把 quad helper 改为四行各六个 SVE 向量，共24累加器；七阶段 kernel 列均单步推进，每个输入立即用于活跃输出行 | 更多输入加载、内层回边和宽块尾部回退可能抵消广播与窗口拼接减少；实际热点已确认无溢出，但首测456.25 ms，比关闭 C6 控制慢0.86%，不采用 |
| [C29-row4lane4](../records/experiments/conv/C29-row4lane4.json) | C26-row4loads | 只在四行共享中段加入四列循环；每输出行以 svld1rq_f32 加载四系数，再用 lane 0→3 的 indexed FMUL 和独立 FADD；原两列及单列余数循环保留 | 专项已通过；实际 d0/d1 两个累加器溢出；首测489.53 ms，比关闭 C6 控制慢8.22%，不采用，不能把全部退化归因于 spill |
| [C30-colchunks](../records/experiments/conv/C30-colchunks.json) | C26-row4loads | 只改 SVE OpenMP 分配：四行组进一步按统一256输出列切块，将组与列块展平为单个 size_t 工作索引，仍用 schedule(static) | 专项已通过，原 quad 热点无溢出；首测447.65 ms、减少1.04%，未超过2.02%波动门槛，保留为探索性复测对象 |

三份候选均不修改 benchmark、runner、源码 README、容差或官方输入，不识别官方尺寸。C28/C29 保持每个输出的 kernel 行、列顺序及分开的乘法和加法；C30 继续调用原 helpers，不进行跨线程部分和归约。源码创建时的 PLAN 保留原始 prepared 状态，后续是否已通过以新取得的专项和性能记录为准。

C28 相对 C24 主循环的静态归一化取舍是：每单位输出×系数的输入加载约增加60%、广播减少33.3%、内层回边增加33.3%；相对 C26 直接窗口加载，归一化输入加载率相同。24个累加器加系数与临时值的约30个 Z 寄存器预算仅是设计推导。实际汇编已消除该候选热点溢出的担忧，但没有据此推断性能。

C29 的源码层面预期是，每四个系数、四行各四向量的工作量仍为64次 FMUL 和64次 FADD、16次完整输入窗口加载；系数加载从两次双列循环共16次 LD1RW 改为4次 LD1RQW。实际汇编已确认64次 indexed FMUL、64次独立 FADD、16次输入加载和4次 LD1RQW，同时观察到两个累加器溢出；首测实际退化8.22%，保留完整记录，不因静态指令减少而采用。

C30 对所有输入统一采用256列，不按公开用例设置分支。块内 helper 获得局部列宽，但相邻输出行地址仍按全局 ow 偏移，输入 stride 保持 inputWidth。不同四行组与不同列块构成不重叠的输出划分；短宽 ow<=256 退化为原来的每组一次 helper 调用。专项已覆盖255/256/257和511/512/513等列块边界、1..3剩余行以及不同 SVE 向量长度，全部通过。

## 目标汇编观察

作业1576127产生的 GCC 10.3.1 严格浮点汇编中，quad 的四行共享中段 `.L335` 每次处理**一个 kernel 列**：

| 观察项 | 实际数量 |
| --- | ---: |
| 主循环指令 | 66 |
| FMUL / FADD | 24 / 24 |
| 输入向量加载 / kernel 广播 | 6 / 4 |
| ext / movprfx | 0 / 0 |
| 向量溢出读取 / 写入 | 0 / 0 |
| 热点栈访问 | 0 |

七个单列阶段均无向量溢出、热点栈访问或 ext/movprfx；全源码 FMA 数为0。外围576字节栈帧包含标量状态及 ABI 保存，不是内层累加器溢出。循环工作量与 C24/C26 的双列循环不同，不能只比较每次循环的指令数就宣称提速。专项插桩及其汇编观察不作为正式性能计时。

C29 的四系数共享 `.L342` 主循环为161条指令、64次 indexed FMUL、64次 FADD、16次输入向量加载和4次 LD1RQW。d0、d1 两个累加器使用向量栈槽，每个四列迭代出现2次读取和2次写入；对应784字节固定帧加2VL，不能混同于 ABI 保存。原双列余数循环内部无向量溢出，但阶段边界和单列余数仍访问这些栈槽。全源码 FMA 数为0。**C29 的121,560项正确性已经全部通过；寄存器溢出属于可能的性能成本，不是数值错误；首测已观察到退化，但尚未通过独立实验分离各成本。**

C30 四行共享 `.L342` 每次处理两个 kernel 列，93条指令、32次 FMUL、32次 FADD、8次输入加载和8次系数广播，与 C26 原 helper 的已审查指令结构相同。七个双列热点均无向量溢出或热点栈访问，共享中段无 ext/movprfx；全源码 FMA 数为0。外围752字节固定栈帧是标量状态与 ABI 保存。C30 改的是外层任务分配，helper 指令相同不能替代整体性能测量。

## 后续仅作探索性复测

根代理正在准备 **C30-r1** 与新候选 **C32-row4lane4staged** 的后续探索性测量；这不是首组获胜后的晋级确认。C30-r1 用于判断约1%的改善能否在新的同资源对照下重现；C32 从 C29 出发，只在四系数循环前半块八个累加器完成后增加一道空 volatile asm 屏障，探索输入提前加载与寄存器溢出的影响。

C32 是独立源码假设，不能借用 C29 已通过的专项或性能结果；需要独立诊断及完整测量。后续作业 ID、顺序、逐次样本和判定由实际回收数据补充，此处不预填结果。C30-r1 即使更快，也不改写本次 C30-colchunks 的 eligible=false 或丢弃 C26-r3 的波动；每次尝试独立留档。
