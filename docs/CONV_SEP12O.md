# CONV：约束四列系数调度

C49-row4dup4fence 基于 C45-row4dup4，只在共享四列循环中加入三段空编译器约束，并让四个 packed 系数成为读写操作数。其目标是缩短跨 kernel 列的寄存器存活，减少 C45 实际出现的向量 spill。它没有硬件屏障、额外算术、输入布局或 benchmark 改动。

原超算作业 1579856 已返回 SUCCEEDED，job/system/wrapper 与全部 19 个阶段退出码为零。实际 GCC 10.3.1 接受三段约束。六种 SVE 16/32/64 字节与 1/4 线程配置各通过 20164 项生产检查和 96 项原有分派 smoke，合计 **121560 项**。逐位标量参考、输入/权重只读、分配边缘保护及输出 canary 均通过。没有 kh=5 动态覆盖、direct 测试、每 case 新循环入口计数、sanitizer 或正式性能结果。

## 与 C45 实际机器安排对照

| 同为四行×四向量，每轮四个 kernel 列 | C45 | C49 |
| --- | ---: | ---: |
| 共享循环指令数 | 185 | 175 |
| 普通 FMUL / 独立 FADD | 64 / 64 | 64 / 64 |
| 输入 LD1W / 系数 LD1RQW / DUP | 16 / 4 / 16 | 16 / 4 / 16 |
| 共享循环向量 spill load / store | 6 / 6 | 0 / 0 |
| C49 保存 packed 值的寄存器 MOV | — | 3 |
| 完整 quad 栈帧 | 784 字节 + 6 VL | 784 字节 |

实际 C49 共享循环为 `.L342`，原 `.s` 第 4719..4894 行。它在更新当前 kernel 列的累加器后，才使用下一列的 packed 系数，安排与 C45 确有变化。三条 MOV 保留系数值；标量地址调度也有差异，因此不能把总共少十条指令解释成纯 spill 成本的减少。两个方案仍为独立乘法和加法，全源没有 FMA。

C49 完整 quad 的七个主循环阶段每次分别为 32/55/75/175/75/55/32 条指令；共享四列循环及原二列/一列余数、非共享阶段余数、过渡、尾列与防御回退均已按实际产物审查。完整 helper 没有 Z/Q/predicate spill；d8..d15 的四对保存/恢复属于 ABI，单独记录。所有 conv2d/OMP 分派已独立审查，仍按四行组覆盖余一至三行，保留原非 SVE 路径及其 tile 写栈。

空模板可能不出现在汇编中，本次没有 #APP 标记。三段原始源码合同结合目标成功编译证明接受；周围调度可观察，但不能给空约束编造指令地址，也不能称为处理器同步屏障。实际只保留了生产 `.s`，未保留生产 `.o`，不宣称对象反汇编一致性。

诊断结束时只证明实际机器安排发生变化，没有性能结论。随后 [N 轮同分配测量](CONV_SEP12N.md) 已完成：C49 为 511.76 ms，C45 为 557.35 ms，结束 C6 为 452.38 ms；C49 仍比 C6 慢 13.1261%。C49 对 C45 的改善也未超过 C45 包含慢样本的波动门槛。诊断原件的 performance_measured=false 反映其冻结时点，后续测量单独保留，未倒改诊断记录。

当前正式最佳仍为 C6，未创建新的提交包。原作业因会话过期发生的一次结果下载认证失败也保留；恢复已授权会话后只取回原作业，没有重复提交或本机算子运行。
