# CONV C58：边界循环展开的正确性检查

C58 基于 C52，仅在十二个边界循环前添加 `#pragma GCC unroll 2`，其余生产文件及官方 benchmark 不变。原作业1583350通过44,328项检查：六种向量长度/线程配置，各5,744项完整卷积、1,212项分派、432项直接调用；19阶段和job/system/wrapper退出均为0。原件已验收归档。

实际 GCC10.3.1 在十二处均生成两列主循环，奇数列通过前置单列路径处理。共享两列主体及单列余项的工作量保持，全汇编没有融合乘加。展开同时带来成本：rowseven helper由父版1,196条指令增加到2,448条，栈帧由720字节增加到720字节+3VL，完整函数静态出现9条向量栈读、15条向量栈写；这些数量不是每次调用的执行次数。仅根据展开或指令数量不能判断提速。

全部编译和检查运行于超算分配的38CPU、24,576MiB、单NUMA节点。本机仅处理源码和日志。检查保留原逐位参考、只读输入/权重、保护页及输出canary；sanitizer未运行。目标汇编审查聚焦这次边界展开、余项和新增栈访问，没有声称重新穷尽所有分派路径或逐条累加链。

本轮没有性能计时，不晋级或生成新ZIP。后续准备与前后两次C6对照各三套的独立性能测量；在实际证明改善前，最佳CONV提交包仍为C6。原C57显式FMA的官方精度失败与此前退化/波动结果保持不变。
