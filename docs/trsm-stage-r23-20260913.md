# TRSM 第二十三轮：成对系数加载改善中例，但未通过晋级门槛

继续保持 **T19-panel8x16budget**。T25 将小路径历史循环的相邻两个系数用同一基址、0/+8 字节偏移加载，按 k、k+1 顺序更新原 16 条累加链，并保留原单步尾项。中用例快 **3.65%**，但大用例慢 **1.41%**，合计改善 **0.74%** 低于 **6.78%** 波动门槛，不晋级。

作业 **1582642** 成功结束，用时 521 秒。本轮调度换到另一计算节点的 **NUMA 0、CPU 0–37**；T19 与 T25 始终在同一分配、同一环境内比较。A=T19、B=T25，独立预热 AB 后按 AB / BA / AB 各执行三套完整官方用例。每套 `TEST_RUNS=3`，每个样本为 benchmark 内部三次计时的均值，不混入此前节点或 NUMA 2 的样本。

小/中/大例耗时减少为 **3.56% / 3.65% / −1.41%**。小例仍走 packed-history 路径，大例仍走 blocked 路径，都不调用本次修改的 8×16 核，不能把它们的差异归因于该机制。保留全部样本，包括 T25 的 12.75 和 184.13 ms；不删除慢样本或合并历史测量。原门槛要求合计改善超过双方逐例最大相对波动及 1%，并且每例退步不超过 1%。合计只是内部比较指标，不是官方得分。

18/18 正式、6/6 预热结果均 PASS，最大误差 1.11e-15。两版各通过完整小路径预检：37 个步骤、27 个测试进程、46 个直接微核、615 个整算子、96 个 no-op、32 个预算组，633 个参数检查用例累计 6388 次观察无不匹配。覆盖零/一/奇偶历史、padding、L 只读、预算边界、行列尾项、禁用 SVE、窄向量和共享/X/全部分配失败，预检最大误差 3.88578e-16。

原源码目标汇编确实生成八对共用基址的 LD1RD，但每两步仍有 **75 条指令**：16 条 ADD、16 条 LD1RD、4 条 X 加载、32 条融合乘加、5 条 MOVPRFX 以及比较分支。T19 两次原循环共 74 条指令。两者热循环均无栈访问；T25 函数栈帧增至 176 字节，含循环外寄存器保存，T19 为 32 字节。

汇编中还有没有被模板文本使用的地址准备。一个待检验解释是，两个单独声明的内存输入要求编译器分别准备地址；下一候选将只把声明改为同一个 16 字节连续内存范围，保持实际两条加载、FMA、索引和尾项完全不变。此时尚未测试新候选，不声称该解释或新方案已经成立。[GCC12 内存输入说明](https://gcc.gnu.org/onlinedocs/gcc-12.3.0/gcc/Extended-Asm.html) 给出了用数组左值描述有界内存范围的形式。[binutils 维护者测试](https://sourceware.org/pipermail/binutils/2016-September/095059.html) 列出 LD1RD 的偏移约束；本轮 0/+8 形式已由实际目标编译和运行验证。

实际使用 **KML25.1 真头文件和动态库、GCC12.3.1 及配套 libgomp**，参考探测和每套依赖检查通过；**不是指定 KML25.2.0 复验**。官方 benchmark、输入、精度及线程限制未改，无本机题目运行、sanitizer 或哈希操作。T19 完整 prior 关联第二十二轮作业 1582526，见[源码、原始结果脱敏副本、环境、命令、prior 与汇编](../records/evidence/trsm-stage-r23-20260913/README.md)。
