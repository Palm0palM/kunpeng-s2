## 实际测量条件

GCC 10.3.1、generic、38 线程、24 GiB、单 NUMA；原 run.sh/benchmark、输入、计时区和精度容差不改。调度、job/system/wrapper 退出码与逐 case PASS 均经登记器核对。各中位数来自三次独立完整套件的打印值，逐 case 波动为 (max−min)/median；包含全部慢样本。公开日志中的个人目录和计算节点另行脱敏。

候选初筛要求合计改善超过对比双方全部逐 case 最大波动与 1% 的较大值，且任一 case 退步不超过 1%；必须同时满足开头和结尾 C6。初筛通过不会自动更新源码或生成提交包。

五个候选均先通过自己的冻结诊断：C45 121560、C46 27408、C47 26112、C48 41664、C49 121560。C45/C49 smoke 没有 kh=5 动态覆盖或逐 case 新循环入口证明。实际汇编、全部 stages 和分派分别审查；没有用未测指令数推断速度。详见 [I](CONV_SEP12I.md)、[L/M](CONV_SEP12LM.md)、[O](CONV_SEP12O.md)。

C47/C48 对 C40-r3 的比较以及 C49 对 C45 的比较在对应实验 JSON 中单独记录，只解释整个形状/编译调度方案的差异，不能把收益归结为纯 spill 成本，也不替代对 C6 的实用性门槛。

C49 相比 C45 合计减少 8.1798%，但 C45 的 A 样本含 71.94 ms，逐例波动达 13.7103%，辅助比较也未达到门槛。消除向量写栈后 C49 仍比 C6 慢 13.1261%。C48 合计只改善 0.9395%，A 用例却慢 2.6807%；C47 的 C 用例慢 1.2395%。因此这轮不会更新提交包。后续优先尝试七行、三向量的中间形状，检验输入共享和寄存器压力的取舍；C50 删除空汇编 memory clobber 的微调保留为待测方案。

登记过程中曾在 C45 开始前退出：创建时的 experiment.json 保留父源码快照，而 checkpoint 把最终源码写入准备记录。实际准备记录、上传清单和返回结果对应同一份候选源码。记录工具改为核对这些实际身份后使用内存中的元数据视图，原创建文件和全部样本不改。恢复时跳过已登记的 C26-r20，沿用原作业完成其余登记，没有重新测量。首次失败、原工具、最小修复和恢复输出均随本轮证据公开留档。
