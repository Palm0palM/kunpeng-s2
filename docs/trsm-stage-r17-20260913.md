# TRSM 第十七轮：4×32 SVE 更新两步展开

本轮保持 **T19-panel8x16budget** 和现有提交包。T20 将大工作集 4×32 更新核的 k 循环展开两步，大用例快 **3.70%**，但合计只快 **1.50%**，未超过 **4.67%** 的波动门槛；中用例慢 **1.70%**，也超过允许的逐例退步范围，因此不晋级。

## 实验与结果

先保持 T19 源码不变，建立无 parent 的当前测量基线 **T19-control13**。独立作业 **1581760** 成功完成三套官方用例，9/9 PASS，登记并晋级后才建立 T20 子候选。初始基线小/中/大例中位数为 13.98 / 119.60 / 181.05 ms，合计 314.63 ms；这批样本不参与后续对照。

对照作业 **1581862** 成功结束，运行 140 秒。同一计算节点、NUMA 0、CPU 0–37，38 线程，各版先执行一套独立官方预热，再按 T19–T20 / T20–T19 / T19–T20 交错执行三套完整官方用例。每套每例的打印值仍是 `TEST_RUNS=3` 的均值；下表中位数取三套独立结果。

18/18 正式结果、6/6 预热结果均 PASS，最大误差 1.11e-15。保留全部样本，不剔除较慢结果。门槛取双方所有逐例 `(max−min)/median` 的最大值和 1% 中较大者，本轮为 4.6676%；总改善须超过该值，且每例不得退步超过 1%。合计只是内部比较指标，不是官方得分。

实际参考为 **KML 25.1.0 真头文件和动态库**，GCC 12.3.1、其配套 libgomp；探测程序和每套链接检查均通过。不是自行构建 OpenBLAS 的校验，也不是题目指定的 KML 25.2.0 复验。不同环境的历史结果分别保存，不混算提速。

## 改动和验证范围

T20 仅展开 `update4x32_sve` 的 k 循环：同一组 16 个累加器依次处理 k、k+1，最后保留奇数尾项；每输出的累加顺序不变。KB256、CT64、内核布局、小路径、分配回退、官方 benchmark、runner、精度和线程设置均保持 T19 原样。

两版各在计算节点通过 28 个直接微核用例、28 个整解用例与 56 个参数检查用例，共 463420 次参数观察、0 不匹配。包括零长度、单项、奇偶尾项、padding、跨行与打包读取、分配失败、禁用 SVE、实际窄向量长度和 KB 尾项。此次修改未涉及的小路径，沿用 T19 作业 1579861 的完整验证；没有将其历史计数写成本轮新测试。没有运行本机编译、测试或 sanitizer。

目标 GCC 汇编中，T19 热循环每 k 为 34 条指令、16 FMLA；T20 每两步为 78 条指令、32 条融合乘加和 8 MOVPRFX，均无热循环栈访问。展开后编译器增加了寄存器搬移，不能只按减少分支推定整体收益。完整汇编、源码快照、命令、环境、逐用例日志和判定见[本轮证据](../records/evidence/trsm-stage-r17-20260913/README.md)。

通过 TRSM 私有无哈希登记流程保留初始基线和重复测量的完整 prior 记录；按用户要求不计算或验证哈希，公共工具未改。当前测量台账为 T19-control13，实现仍是 T19。下一步先做 T20 同源码确认，不降低门槛。
