## 静态核对与待验证风险

C23 与 C21-r3 的源码差异恰好三行，均位于三行共享中段：x0/x1/x2 从相邻拼接改为偏移 1 的直接加载。各 lane 读取相同的只读 input 元素，三输出的 k0→k1 和 kernel 行列顺序未变；新增三个窗口的末列均低于原最后偏移窗口的上界，未扩大合法输入边界。README、benchmark 和 runner 的字节哈希与控制一致。目标汇编已经证实共享中段去掉 ext/movprfx，首组同资源测量观察到 3.14% 的合计耗时下降；收益仍需独立复测确认。

C24 独立只读审查未发现遗漏。七阶段输入行 0、1、2、3..kh−1、kh、kh+1、kh+2，使四输出各自恰好接收 kernel 行 0..kh−1，且每个向量保持 k0→k1。kh<4 调用原 triple 加第四行 prefix；剩余三/二/一输出行分别调用原 triple/pair/prefix。组数 `oh/4+(oh%4!=0)` 避免 oh+3，最大组起点 `j=4×group<oh`；用 oh−j 判断余行，第三/第四输出偏移和 kh+1/2 都先扩为 size_t。最大输入行 `j+kh+2<=inputHeight−1`，最后横向偏移窗口不越界，输出组之间互不重叠。这些路径随后均纳入了已通过的计算节点专项校验。

C25 只扩展原三行 helper 的五阶段，a、a/b、a/b/c、b/c、c 都补齐第五和第六向量，奇数末系数与三行 store 完整。最后 k1 窗口采用 `p+5×VL+1`，未额外加载完整 v6；由 `i+6×VL<=ow`、`ik<=kw−2` 得到末列不超过 `inputWidth−1`。最大输入行仍为 `j+kh+1<=inputHeight−1`；原三行组调度、kh<3回退及所有旧 helpers 不变，四至六向量之间余数可由原 tail 覆盖。十八累加器和六个 kernel 广播的目标代码确实发生了一个累加器的向量栈溢出；实测合计仅降低 0.66%，未达到晋级门槛。当前对照不能单独量化溢出的耗时成本。

C23 的五个双系数热点均无栈访问或向量溢出，共享中段的 ext/movprfx 确实消失，其他首尾阶段仍保留原拼接。C24 七个双系数热点同样无向量溢出，720 字节外围栈帧中的地址及 ABI 保存不能算作热点向量溢出。

**C25 共享中段每处理一对横向系数，都要从 `sp+912` 对应槽读取并写回一个向量累加器。** 完整栈帧为 912 字节加一个 VL；这个真实的可变宽度向量槽不同于外围标量地址保存。其他四个双系数热点内部没有向量溢出，但阶段转换和奇数列路径也读写同一槽，不能把它们误写成全函数无溢出。

首组三份完整源码及续跑的 C26、C27 均未生成 FMA。C26 共享中段从 C24 的 96 条变为 93 条，输入加载 5→8、ext/movprfx 各 3→0；七个双列热点没有向量溢出或栈访问。C27 的五处空 asm 约束确实改变了调度，共享中段仍为十八累加器，105 条指令，C25 的 `sp+912` 向量读写及额外 VL 栈槽已消失；五个双列热点均无向量溢出，外围固定 912 字节栈帧仍用于标量地址与 ABI 保存。不同候选的块覆盖范围不同，静态指令数和溢出观察不能直接当作耗时或提速结论。
