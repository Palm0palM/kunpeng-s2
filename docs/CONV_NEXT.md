# CONV 第二轮实验计划与证据

本轮已经确认首次提速并晋级为 **C1**：显式四向量 SVE（实验 C7-sve64）在同作业、相同 38 核与 NUMA 下，四组用例三轮中位数合计从 1867.33 ms 降至 642.91 ms，耗时减少约 65.6%，每组误差均为零。正式晋级标签与实验编号的对应见 `records/conv-lineage.json`；后续最新结果以 `docs/CONV_ROUND_RECORDS.md` 为准。

随后以 C1 为新基线进行同组对照，四向量复测 643.06 ms，八向量 C8-sve128 为 630.50 ms，四组用例均改善，耗时再减少约 1.95%，晋级为 **C2**。两次优化分别有各自同资源对照，不把跨 NUMA 的独立运行直接相除当成受控加速比。

延续 C0-r2 的已验证源码。本轮每个实验独立命名并记录父版本、假设、源码 SHA-256、正确性、三轮耗时、调度器状态与判定。`C0-rN` 是原版复测编号，源码没有改变；`C4` 等是候选实验号，不表示已经获得第四次提速。真正晋级时另在记录中给出对应关系。

C7-r1 与 C8 同组、顺序各运行三轮。本轮最后一组以 C2 为基线：C8-r1 复测 629.91 ms，C9-sve256 十六向量为 649.39 ms，慢约 3.09%，四组用例均未改善，拒绝晋级。最终仍为 **C2**，`C8-r1` 只表示同一代码的复测，不生成 C3。所有正式组作业成功，逐组正确性通过、最大误差为零。

本轮共保留 11 个测量记录（6 个候选与 5 个复测基线），以及独立硬件和边界诊断。SVE 四/八向量在本机回退路径及真实 SVE 路径分别完成 1/4 线程 616 组边界检查；十六向量为 682 组。服务器没有执行 sanitizer，UBSan 证据来自本机回退路径。工作流共 66 项回归检查通过。

后续可研究 SVE 尾部处理，减少回退到通用路径的输出；当前代码的余数处理可能影响较大主块的收益。这是尚未测量的假设，不能作为新增提速结论。

## 比较方法

C0-r4、C4、C5、C6 使用同一个调度作业，顺序执行各自独立包装器，保证同一组 38 个 CPU 和同一个 NUMA。每项运行三轮完整官方套件，保留逐用例原始值、中位数及波动。组内任一成员失败会使整个作业失败，不把缺少调度器成功凭据的结果晋级。

`tools/cluster_group.py` 只负责把独立实验放进同一资源分配；每个实验仍通过 `tools/cluster.py status/fetch` 和 `tools/experiment.py record/compare` 完成验证。每项记录共享的作业 ID、测量顺序和自己的源码哈希；不重复提交已有 ID。

## 已确认的硬件诊断

轻量调度作业证实 SVE 向量长 64 字节（16 个 float lane），最小 load/mul/add/store 探针编译并执行成功，错误数为零。GCC 10.3.1 的 native 选项识别目标 CPU，但现有代码的 native 主循环仍采用 NEON，并出现额外栈访问；generic+sve 自动向量化也产生累加器栈读写。因此下一步使用显式 SVE 累加器，不凭编译选项名称判断快慢。

官方 benchmark 和容差保持原样；SVE 候选仍使用分离乘法和加法、原始累加顺序。编译成功或最小探针通过不等于正式大用例通过，也不构成性能结论。

## 公开与本地记录

`.runs/` 保存不可公开的真实连接元数据及完整原件。推送前输出公开副本，移除真实内网地址、账号、个人目录和内部节点名，保留策略、性能数值、正确性和源码身份。公开日志与原始哈希的关系要明确注明，不用脱敏副本冒充原件通过自动验证。

每项未提速或失败的候选都保存结论；三题目录只维护已有测量证据支持的最佳源码。正式平台分数和排名在实际取得前留空。
