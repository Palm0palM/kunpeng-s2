# TRSM 第十三轮：共享 L 生产循环调度

本轮 **不晋级，保持 T8-svepanel16 与现有提交包**。T14 将共享历史生产循环改为循环静态分配后，中用例仍比 T8 慢 **11.28%**，合计慢 **4.83%**；相对同期 T10，中用例慢0.09%、合计慢0.40%，没有改善证据。作业 **1579673 SUCCEEDED**，调度与进程退出成功，27/27正式结果、9/9预热及全部预检通过，最大官方误差1.11e-15。

A=T8-control12-repeat-r13、B=T10-lhistbarrier-repeat-r13、C=T14-lhistcyclic。A/B保持原实现身份，分别保留r12作业1579645、r7作业1579401的完整prior；这两个历史来源不同。T14从未晋级T10出发，唯一源码改动是共享packed_history生产循环的 `schedule(static)` 改为 `schedule(static,1)`。复制布局、空asm约束、消费者调度、隐式barrier、分配与回退及大路径均不变。T14晋级父版本仍为T8，T10仅作为该pragma改动的同期对照。

同一计算节点、NUMA2、CPU76–113，38线程、24GiB、1800秒上限，实际运行约242秒。使用Huawei KML25.1.0真实头文件和默认-lkblas、GCC12.3.1及其私有libgomp；每套实际依赖检查通过，没有OpenBLAS。**不等同指定KML25.2.0复验**，不与不同作业或历史OpenBLAS/GCC10结果混算收益。官方runner、benchmark、尺寸、计时区与1e-12精度不变。

两个候选均违反合计改善与逐用例不得退步超过1%的晋级要求。T10/T14机理比较也未通过；其原始比较结果中的eligible字段不授权晋级，真正晋级必须重新核对T14的T8父版本。合计只代表逐用例中位数之和，不是官方分数。三个版本的大路径源码相同，其大例差异不能归因为本轮小路径调度改动。

T8通用预检通过14组直接核、406组整算子、28组空操作；T10/T14各通过28组直接核、486组整算子、36组空操作，其中各80组验证仅共享历史分配失败而后续X分配成功。实际检查覆盖1/4/38线程、边界与padding、L只读、无SVE、实际窄VL、全部分配失败和共享历史独立回退。预检按源码特征分别核对完成数量，不用统一计数代替。未运行服务器sanitizer。

循环静态分配的工作量模型曾将中用例各线程复制权重范围由10–586降到228–376，但复制总量不变，且它不是阶段耗时测量。本轮整题结果没有显示收益，不能继续把线程工作量更均衡当作性能改善或认定原退化原因。

实际目标汇编确认T14生产循环以线程编号加1开始、以线程数为步长推进，T10仍为连续静态分块；两者生产后均保留barrier。T10/T14的packed-L历史热循环各37条指令，含16次系数广播、1次X向量加载、16条FMA，没有热循环栈访问或调用。[独立日志与汇编审查](../records/evidence/trsm-stage-r13-20260912/cohorts/compare/assembly-review-lhistcyclic.md)区分实际生成代码与未验证的性能原因，未在本机重新生成汇编。

下一步准备限制共享历史副本的分配预算，再与大路径4×32更新组合比较。预算采用已安全计算的实际packed_history字节数，不按官方M/N硬编码，也不声称它是硬件缓存大小。超过预算保持NULL，沿现有旧核回退；该方案及组合版本尚未测试，不能根据T10小用例收益直接晋级。
