## 组合身份与作用域

唯一切点是 `source/trsm.c:677` 的 `enum { KB = 256, CT = 64 };`。切点之前完整文本与 T17 相同；从 enum 到文件末尾完整文本与 T13 相同。切点的预处理嵌套深度为 0，函数/代码块已经结束。没有夹带 T13 的旧 solve_panel，没有重复函数定义。

前缀提供 RHS=8、ROWS=4、标准头文件、AArch64 NEON、条件 SVE 包含和 TRSM_CAN_DISPATCH_SVE 定义，包含完整 T17 solve_panel。后缀自带全部 update 核、solve_blocked 和 l_trsm。92 行 `trsm_sve_has_eight_doubles(void)` 前向声明与 753 行定义一致，target/noinline 属性相同，声明/定义各一次。l_trsm 在 1143 行定义并可见此前 solve_panel，无遗漏跨切点依赖。重复的标准头文件包含是原布局，无新增冲突。

预处理条件文本嵌套平衡；函数名逐项检查无重复。bench_trsm.c、run.sh、compat/kblas.h、README.md 与 T10 对应文件逐字节相同，前三份也与当前 trsm 官方控制文件一致。因此没有以组合为由改用例、容差、runner 或线程约束。

## 小路径预算继承

561 行预算常量和 578 行分配门禁与 T17 完全一致，预算只包住安全 bytes 计算后的共享分配。m=1024..1039 的 b=64 副本为 4,128,768 字节，允许尝试；m=1040 的 b=65 为 4,259,840 字节，超过 4MiB。预算依赖完整 16 行块的实际副本形状，没有官方尺寸等值判断。

packed_history 在并行区外初始化/分配，超预算 NULL 为所有线程一致的共享状态；生产区及 barrier 一致跳过，完整行块自然进入原 panel16 核。原两道整数溢出保护、预算内分配失败、每线程 X 失败、行列尾部和释放语义全部继承 T17；详见 T17 的 STATIC-REVIEW.md。这不是把 T10 或 T13 的历史成绩当作 T18 成绩。

## 大路径接口、完整列区与尾部

update4x32_sve 在 880 行，八个参数分别为 count、L、lda、X0、ldx、panel_stride、C、ldc。后缀调用均传入相同签名，count=end-kk；SVE 只能在硬件可用且当前线程恰为 8 个 double lane 时使用（962、967 行）。

共享面板布局仍为 `[ceil(n/8)][KB][8]`。正常路径 X0 指向 `packed+(j/8)*KB*8`，ldx=8、panel_stride=KB*8=2048 个 double；X1/X2/X3 分别推进一、二、三个完整 8 列面板。packed 分配失败时 X0 改为 `B+kk*ldb+j`，ldx=ldb、panel_stride=8；四个指针就对应原 B 的 j、j+8、j+16、j+24 列。C 的 ldc 独立传入 ldb，没有混淆 packed 的行步长。

三处完整 32 列分派保留原 T13 结构：1035–1044 行在至少 16 行时调用四次 4 行核，1065–1072 行在至少 8 行时调用两次，1095–1105 行剩余行只有至少 4 行才调用一次。每处均要求 j+32<=je，故四个完整面板不会越过当前 CT 列区；CT64、32 和 8 步长保持面板对齐。后续余列仍依次由原 16×8、8×8、4×8 或标量处理；不足 4 行不会进入 4×32。没有合入未晋级 T11 的 8×16 或其它宽核。

新核的 16 个累加器仍全部从零开始，k 从 0 到 count-1 单调增加，结束后每输出仅做一次 C-sum；与整个 T13 后缀直接文本相同。大路径生产对角块后的 omp-for barrier，以及 update 的 collapse(2) static 工作分派不变。packed 失败读取的是已完成对角块的 B，输出区 ib>=end，不和当前读取行相交。

## 非 SVE 文本路径与使用限制

所有 SVE 函数、helper、have_sve/use_sve 和宽分派引用都在 TRSM_CAN_DISPATCH_SVE 保护中。该宏为 0 时小路径去掉预算/共享历史代码，大路径宽分派移除后 j 从 jb 开始进入原 8 列循环。AArch64 使用原 NEON 满 4×8 路径，非 AArch64 移除相应条件和 else 后保留标量循环；未发现 dangling else、悬空 use_sve 或不可见类型引用。这里是源码分支审查，没有执行预处理器或编译器，不能宣称已编译通过。

VALIDATION-PLAN.md 已明确预算边界/分配观测与独立 wide32 预检都需要完成。4097×9 虽进入大算法，但列数不足 32，不能证明宽核入口；完整 32 列、CT64 尾部、packed 失败、无 SVE 和真实窄 VL 仍需本轮实际日志。未读取开发中的预检，计划计数未被本报告认定为通过。

同作业 T17-vs-T18 可用于隔离该大路径替换，T8 仍为晋级父基线；机理对照不单独授权晋级。不得把静态组合完整性推断为性能收益。实际 KML25.1/GCC12 与指定 KML25.2 复验范围继续分开记录。
