# C33-row5x4u1：五输出行 × 四向量，kernel 列单步推进

- parent / source_parent：C26-row4loads，正式 C6 的源码来源。当前正式测量仍为 C26-r1；C33 是新源码候选，不以任何旧测量替代自身验证。
- 状态：prepared。仅轻量源码/文档编辑和静态审查，尚未编译、做专项或测量性能；不加入正在运行的1579297探索组，不申请新计算作业。
- 单一假设：把相邻输出行共享从四行扩到五行，每行四个 SVE 向量，共20累加器，kernel 列单步推进。在五行都参与的共享中段，相对 C6 双列四行方案降低每单位工作的输入加载率，保留系数广播率。实际收益可能被更频繁的内层回边、更大的状态及线程尾部不均抵消。

## 实现范围

新增 `conv_sve_rowquint`，标记与原 SVE helpers 相同的 target/noinline 属性。只增加一个 SVE 外层分支：`use_sve && kernelHeight>=5 && oh>=5` 时按五行组 `schedule(static)` 分配；完整五行调用新 helper，最后4/3/2/1行依次调用原 quad/triple/pair/prefix。各输出行地址都使用全局 ow，输入 stride 仍为 inputWidth。

kernelHeight<5 或 oh<5 时完整走原 C6 SVE 分派；非 SVE 时完整走原非 SVE 路径。旧 C6 helpers、旧四行调度分支及后续非 SVE 循环原文保留，不修改 benchmark、runner、源码 README、容差、flags 或官方输入，不识别官方尺寸。

quint 满块宽度为4*svcntw()。每个 kernel 列先广播当前活跃行系数，再按四个向量位置逐个加载输入并立即更新活跃行累加器；每个输入有独立的源码作用域，不额外添加 asm。源码作用域不能保证编译器最终调度。尾部不足4VL的列交给原 quad 加第五行 prefix；helper 的 kh<5 防御性回退也调用原 quad+prefix，正常外层分派不会以小核进入 quint。

## 九个输入行阶段与数值顺序

输出行编号为0..4，对应 a/b/c/d/e。输入行 t 递增；输出 r 在参与时只使用 kernel 行 t-r。

| 输入行 t | 活跃输出及 kernel 行 |
| --- | --- |
| 0 | a:0 |
| 1 | a:1，b:0 |
| 2 | a:2，b:1，c:0 |
| 3 | a:3，b:2，c:1，d:0 |
| 4..kh-1 | a:t，b:t-1，c:t-2，d:t-3，e:t-4 |
| kh | b:kh-1，c:kh-2，d:kh-3，e:kh-4 |
| kh+1 | c:kh-1，d:kh-2，e:kh-3 |
| kh+2 | d:kh-1，e:kh-2 |
| kh+3 | e:kh-1 |

kh>=5 时，上表每个输出恰好按 kernel 行0..kh-1接受所有贡献；所有阶段内部 `ik` 都从0逐次到kw-1，包含最小 kw=1。每个输出始终用一个累加器，初值0，每项仍是独立 `svmul_f32_x` 再 `svadd_f32_x`。不拆分部分和、不横向求和、不重关联、不引入 FMA；原 `-fno-fast-math -ffp-contract=off` 保持。改变不同输出之间的交错不改变各输出本身的运算顺序。数值相等目前是源码推导，逐位参考和实际编译仍待超算验证。

## 主循环归一化取舍

只比较全部输出行都活跃的共享中段，不把这张理论表称为实际汇编或计时。

| 每次内层迭代 | C6：四行×4VL，双列 | C33：五行×4VL，单列 |
| --- | ---: | ---: |
| 输出向量×kernel列工作量 | 32 | 20 |
| 独立 mul / add | 32 / 32 | 20 / 20 |
| 输入向量加载 | 8 | 4 |
| 系数广播 | 8 | 5 |
| 内层回边 | 1 | 1 |
| 输出累加器 | 16 | 20 |

输入加载率从8/32降至4/20，约减少 **20%**；系数广播率8/32与5/20相等。内层回边率从1/32变为1/20，约增加 **60%**。完整输出行组数约减少20%，横向块宽不变；但首尾部分增加到九个阶段，相对七阶段 C6，在小 kh 时非共享部分占比更高，不能把共享中段20%直接当作全函数收益。

理想流式预算约为20个累加器+5个系数+1个输入+1个乘积=27个 Z 寄存器，仅为设计估计。编译器可能同时持有更多输入和乘积、增加搬移、在阶段间延长活跃范围或产生 spill。五行组减少可分配任务数并扩大每个任务工作量，可能恶化38线程的尾部负载不均。更多回边、状态和回退成本也可能导致整体退化；必须以实际目标汇编及同资源测量判断。

## 地址与整数边界

- 原 conv2d 先检查 kernelHeight/kernelWidth>0 和输入不小于 kernel，再计算 oh/ow；正合法 int 输入满足1<=oh<=inputHeight、1<=ow<=inputWidth，保留原有效足量缓冲区前提。
- 新调度先把 oh/ow 转 size_t，组数用 `output_rows/5+(output_rows%5!=0)`，不计算 oh+4。有效 group 下 `row=5*group<oh`；因此 `remaining=oh-row` 为正，不下溢，且不需要用 row+4 判断边界。
- 只在 remaining>=5 调用 quint。输入最大行是 `row+kh+3=(row+4)+kh-1<=inputHeight-1`。其余输出行用原 helper，不扩大原有访问范围。
- quint 的 kh+1/2/3 在加法之前转为 size_t，kernel 行地址先转 size_t 再乘 kw。kh>=5 保证所有 kh-1..kh-4 和 t-1..t-4 非负；最大kernel行仍为kh-1。
- 满向量条件 `ow-i>=4*lanes` 保证 i+4*lanes<=ow。最大输入列为 `i+(kw-1)+4*lanes-1<=ow+kw-2=inputWidth-1`；只有当前完整窗口，没有额外向量预读。i 只在该条件成立时加block，所以 i+block<=ow，不新增 int 溢出。
- 输出最大列 i+4*lanes-1<=ow-1；五个输出指针以全局 output_stride=ow 逐行偏移，均使用 size_t 运算。AArch64 64位 size_t 足以容纳32位尺寸的行×行距乘积；和原接口一样，调用方须提供可表示且足够大的实际数组。
- 各组覆盖 `[5g,min(5g+5,oh))` 不重叠且完整，组内各向量/尾列也不重叠。每个输出只有一个线程写入，无原子操作或跨线程 reduction。
- 不支持 SVE 或未定义 CONV_CAN_DISPATCH_SVE 的构建不进入新 helper；generic conv2d 未增加 svcntw 或其它 SVE intrinsic。旧非 SVE 文本保持原样。
