## 观察依据与单一假设

C29 专项作业1579242已完成121,560项检查，全数通过。根代理回收的目标汇编观察为：四系数 quad 共享循环161条指令、64次 indexed FMUL 和64次独立 FADD、16次输入窗口加载、4次 LD1RQ；每迭代有两个累加器溢出，各对应一次向量栈读取与写入，即2 load + 2 store；全源码 FMA 为0。这里只引用已回收诊断，不把它当作 C29 或 C32 的性能结论。

单一假设：C29 的16个输入窗口跨越前后两个向量位置组提前加载，可能延长存活范围并增加寄存器压力。在四系数新循环完成 n=0、n=1 的全部 lane 0→3 累加后，加一道空 volatile asm，使前八个累加器必须先完成，再允许后半块的输入窗口加载跨越该点。希望减少窗口跨半块的提前加载，而不是每个向量位置都分隔一次。

## 唯一源码变更

只在 `conv_sve_rowquad` 的 `kw-ik>=4` 共享中段循环内，在 n=1 的 lane3 更新后、n=2 的 lane0 输入加载前插入：

```c
/* Complete the first eight accumulators before later window loads. */
__asm__ __volatile__("" :
    : "w"(a0), "w"(b0), "w"(c0), "w"(d0),
      "w"(a1), "w"(b1), "w"(c1), "w"(d1)
    : "memory");
```

八个输入约束均为 `w`；没有输出约束、实际汇编指令、寄存器覆盖或新增内存访问。memory clobber 是编译器对内存访问的约束，不是硬件内存屏障，也不是线程同步。四个系数向量的加载位置和内容保持不变，原有16个累加器仍都保留。

屏障点只消费已完成的 a0/b0/c0/d0/a1/b1/c1/d1；n=2/3 的八个累加器仍各自沿原 lane0→1→2→3 顺序继续。每个前后半组包含八条相互独立的累加链，比 C27 每组消费三个累加器留出更大的调度范围，但不保证足以隐藏运算延迟。

## 预期风险与待验证事项

一道屏障可能缩短部分输入窗口的存活范围，也可能因为八个指定值必须同时在寄存器中而增加搬移或溢出。其它输入、系数和后半块累加器仍然存活，不能把“前半块完成”理解为只剩八个累加器占用寄存器。编译器还可在屏障两侧各自重排，或提前保留不受影响的值；空 asm 不保证最终消除两个 spill。

memory clobber 还可能抑制有利的提前加载、流水重叠或公共读取优化，延长依赖等待。因此即使实际无 spill，C32 也可能像此前 C27 一样更慢；不能根据指令或寄存器变化晋级。C27 的失败仅用于提示调度风险，不跨不同源码、工作量或分配计算严格性能差值。
