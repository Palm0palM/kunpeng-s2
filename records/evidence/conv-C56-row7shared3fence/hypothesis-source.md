# C55 下一假设：在三个列末约束全部累加器

建议只试一个改动：在 C55 shared 的三个完整列作用域之后，各插入同一条 **21 个只读向量输入＋`memory` clobber 的空 asm**。这是减少跨列同时活跃值的可检验假设，不能保证消除 spill 或提速。本报告只读分析，未创建候选或运行工具、编译、SSH、作业。

实际依据是 AC1582860 的 `sep13ac-checks/C55-row7x3shared3/raw/conv2d-sve.s` 与同目录 `HELPER_REVIEW.md`。生产源 SHA256 为 `cc6b51603928d7f7825f86ac09d139ec3e3846c8c40946e16fa9d110eb1a8138`，汇编 SHA256 为 `0843c7259fdcb63d78d37965de48c229f81a505f59df81eb579fd792452aa39c`。

实际 `.L407`（6403–6592）每三列为 189 指令、63 FMUL/63 FADD、9 LD1W/21 LD1RW，5 次 Z 栈读、5 次写。五槽 `SP+880+n*VL` 分别携带 **a2、c1、d1、c2、d2**。例如 a2 在 6432 重装，6438/6439/6440 顺序加三列，6444 写回。编译器没有保持源码列作用域：a0 的三列加法在 6413/6415/6421 已完成，而 b0 第一列到 6511 才发生。输入窗口和系数的跨列重叠，是值得约束的压力来源；仅凭该汇编不能证明它是五槽的唯一原因。原 C52/T 两列 123 指令且无 Z spill，提供参照，不能代替新方案证据。

插入点是 `.runs/conv/C55-row7x3shared3/source/conv2d.c` 原始行 **1530、1571、1612 之后**，分别紧接 `column=ik`、`ik+1`、`ik+2` 的作用域关闭。三处各使用以下完整语句；不改三列算术、`kw-ik>=3`、`ik+=3`、原 u1 余数或其余阶段。

```c
__asm__ __volatile__(""
    :
    : "w"(a0), "w"(a1), "w"(a2),
      "w"(b0), "w"(b1), "w"(b2),
      "w"(c0), "w"(c1), "w"(c2),
      "w"(d0), "w"(d1), "w"(d2),
      "w"(e0), "w"(e1), "w"(e2),
      "w"(f0), "w"(f1), "w"(f2),
      "w"(g0), "w"(g1), "w"(g2)
    : "memory");
```

每处的输入依赖要求本列全部 21 个结果先可用；`memory` 尝试阻止后列输入/系数读取越过该边界，第三处也约束下一轮。它没有输出依赖，不能宣称所有寄存器运算都被完全隔离；`volatile` 本身也不是绝对调度屏障。空模板不改变累加器、内存或浮点顺序，不发出硬件 fence；编译器仍可能插入额外重装和移动。原每条链 `ik→ik+1→ik+2` 的独立 FMUL/FADD、边界地址与线程存储关系保持原源码语义。[GCC 10.3 Extended Asm](https://gcc.gnu.org/onlinedocs/gcc-10.3.0/gcc/Extended-Asm.html)

选择 21 个输入、0 个输出：总数 21，低于 GCC 的 30 操作数上限；21 个 `+w` 会按输入加输出计为 42，不能采用。空模板也不应虚构 `=w` 写结果。`w` 是 AArch64 向量寄存器类，覆盖 SVE；不固定寄存器、不添加寄存器 clobber。21 个同时受约束的值仍可能使实际 GCC10.3.1 分配失败或增加 spill，符合数量上限不等于保证编译成功。[GCC 10.3 操作数规则](https://gcc.gnu.org/onlinedocs/gcc-10.3.0/gcc/Extended-Asm.html)，[GCC AArch64 约束](https://gcc.gnu.org/onlinedocs/gcc/Machine-Constraints.html)

后续若另行授权创建候选，必须先看真实 GCC10.3.1/generic/原严格浮点 flags 生成的机器证据：

- 按数据流核对三列边界是否实际收紧：每列 21 个 FADD 的完成与后列 LD1W/LD1RW 的位置，而非仅看源码括号或空 asm 标记。仍须是三列 63 FMUL/63 FADD、相同逻辑输入/系数读取与各链列顺序，无 FMA、重关联或遗漏。
- 目标是每轮 5 读/5 写减少，并检查**整个 helper**，防止只是把 spill 移到三个 asm 周围、循环外或外围阶段。目前全 helper 静态 30 LDR Z/45 STR Z、frame `880+5VL`；其中包含阶段转换及防御分支，不能当作每轮动态计数。新报告应分别列出热循环、转场、整函数和实际栈框架，另列 D8..15 ABI、Q/谓词及标量栈。
- 保留 13 阶段、u1 余数 0/1/2、21 输出、dispatch/tail/fallback 的完整审查；新源须有自身六 VL/线程配置的 44328 数值与全部退出证据，父 AC 的 PASS 不能继承。汇编若未减少有效热路径栈访问，或用更多载入/移动换取表面零 spill，就没有支持该假设。

主要风险是三个边界各强迫 21 值进入寄存器，可能把当前每三列一次的重装变为每列一次；`memory` 也可能限制有利的载入提前和复用，改变全函数分配及标量栈。即使零 Z spill，也可能因调度受限而更慢。因此值得一次有界的源码/实际代码生成验证，不足以直接主张性能实验成功。准备分析完成，STOP。
