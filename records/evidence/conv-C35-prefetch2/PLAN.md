# C35-prefetch2：四行共享中段提前两行预取

父版本与源码来源均为 **C26-row4loads**，即正式 C6 的源方案。C35 是独立候选，不改变当前最佳，不继承父版本的通过状态或性能结果；本次只准备源码、静态审查及 checkpoint，停在 prepared。

唯一假设是：在当前四行共享输入行 t 开始前，为同一横向满块的输入行 t+2 发出四个读预取提示，或许能让部分后续输入在使用前到达缓存，隐藏加载延迟。**没有 cache-miss、加载停顿或硬件计数器数据支持这一解释，也没有 C35 的性能结果。** 四次预取可能重复硬件预取、没有足够提前量、增加地址/分支指令，或挤占 L1 容量与请求资源，最终可能无收益甚至退化。

## 唯一代码改动

只修改 `source/conv2d.c` 的 `conv_sve_rowquad`，在现有 `for (int t = 3; t < kh; ++t)` 循环体开头加入：

```c
if (kh - t > 2) {
    const float *future = base + (size_t)(t + 2) * stride + i;
    __builtin_prefetch(future + 0 * lanes, 0, 3);
    __builtin_prefetch(future + 1 * lanes, 0, 3);
    __builtin_prefetch(future + 2 * lanes, 0, 3);
    __builtin_prefetch(future + 3 * lanes, 0, 3);
}
```

`rw=0` 表示读提示，`locality=3` 表示高时间局部性提示；具体目标指令及是否采纳由编译器和处理器决定，不能据源代码断言必然驻留 L1。只预取四个完整输出向量对应的输入起点，不按 kernel 列追加预取、不预取权重，不增加完整向量实际加载。首三行、末三行、双系数/单系数算术、SVE helper 及尾部回退、OMP 调度、非 SVE 路径原样保留；不改 benchmark、runner、README、编译选项、容差或官方尺寸。

## 地址与整数边界

- quad 的 kh<4 路径提前回退；共享中段真实范围是 `3<=t<kh`。在此范围 `kh-t` 为正且不会溢出。先检查 `kh-t>2`，再形成 `future`，不是先形成可能非法的地址再决定是否使用。
- 条件成立推出 `t<=kh-3`，因此 `t+2<=kh-1<=INT_MAX-1`，int 加法安全。行距乘法在转换为 size_t 之后进行，预取行是原本合法的共享输入行，不进入 kh/kh+1/kh+2 的尾部阶段。
- 设当前四行组起点为输出行 j。quad 仅在至少四个输出行存在时调用；本次预取最大行 `j+t+2<=j+kh-1<=inputHeight-1`，没有扩大既有 quad 所需的输入行范围。
- 满块循环条件 `ow-i>=4*lanes` 保证 `i+4*lanes<=ow`。四个起点最大为 `i+3*lanes`；最后一个完整向量的末列为 `i+4*lanes-1<=ow-1<=inputWidth-1`。因此不仅提示地址本身，连对应的完整向量范围也合法，不形成额外 v4 地址。
- kh=1/2/3 走旧回退；kh=4/5 的共享循环不发出预取；kh=6 仅 t=3 预取行5。更大奇偶 kh 统一按条件处理，最后两个共享行不再预取。kw=1、窄输出和可变 VL 沿用既有约束，不识别官方 shape。
- 和原接口一样，调用方须提供有效且足够大的实际数组。预取不放宽 C 指针形成规则；不以“预取通常不触发异常”替代以上边界证明。
