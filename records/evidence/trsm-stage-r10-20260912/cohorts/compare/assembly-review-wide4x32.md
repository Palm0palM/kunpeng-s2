# T13 4×32 更新核实际目标汇编审查

2026-09-12。只读分析 r10 作业 1579585 取回的 `assembly-review-inputs/trsm-wide4x32.s`，并以同期 `assembly-review-inputs/trsm-T8.s` 的 `update16x8_sve` 为对照。下文行号为各自 `.s` 文件的一基行号，指令计数排除标签、对齐及 CFI 等汇编指令伪操作。没有本机编译、生成汇编、运行测试、SSH 或计算/验证哈希。

**新核实现了四个 L 系数各供四个 X 向量使用，每 k 16 条 FMA，热循环 34 条指令；整个微核没有栈访问或核内调用。** 同期 T8 16×8 热循环为 52 条指令。T13 同时增加 X 加载、输入有效载荷和 C 回写地址计算；本文不由指令数量判断性能或晋级。

## 生成对象与比较范围

两份 `.s` 的 `.ident` 都为 `GCC: (gcc for openEuler 3.0.2) 12.3.1`。T8 文件来自通用预检的原候选 `trsm.c` 汇编产物；冻结 `payload/preflight/run.sh` 第 49 行的 assembly 命令使用 `flags` 和 `-S`，没有附加前面构建检查程序时使用的 `test_flags`。T13 对应 `payload/preflight-wide32/run.sh` 第 60 行，同样从原候选 `source_dir/trsm.c` 生成 `trsm-wide4x32.s`，未使用 `instrumented-trsm.c`。

上述冻结脚本的 assembly flags 均为 `-O3 -fno-fast-math -ffp-contract=off -fopenmp -mcpu=generic`。检查程序的 `-finstrument-functions`、TEST 宏和参数观察插桩只用于另行构建的预检程序；这两份汇编均未发现 `__cyg_profile`、`trsm_test` 或 TEST 符号。这里比较的是原源码编译得到的微核，不把插桩观察开销计入微核。本审查不额外建立汇编文件与最终 benchmark 二进制的字节身份声明。

## 每 k 的实际热循环

T13 的 `update4x32_sve` 为 456–623 行；正 count 热循环 `.L25` 在 488 行，指令主体为 489–522 行。T8 `update16x8_sve` 为 144–385 行，热循环 `.L14` 主体为 224–275 行。每次调用分别更新 4×32 和 16×8，均为 128 个 double 输出。

|每 k 的实际项目|T8 16×8|T13 4×32|
|---|---:|---:|
|L 系数内存加载数|16|4|
|`ld1rd` 加载并广播|16|1|
|标量 `ldr d`|0|3|
|`mov z.d,d` 广播|0|3|
|X 向量 `ld1d`|1|4|
|`fmla`|16|16|
|地址 `add`|17|4|
|循环内 `ptrue`|0|1|
|`cmp` / `bne`|1 / 1|1 / 1|
|热循环指令合计|52|34|
|热栈访问 / 核内调用|0 / 0|0 / 0|

T13 的 492 行 `ld1rd z7.d` 读取第 0 行系数；489、491、493 行分别以带行偏移的寻址加载第 1、2、3 行到 d2/d1/d0，497–499 行再广播到 z2/z1/z0。因此是四次 L 内存读取、七条系数读取/广播指令，不能写作四条 `ld1rd`。

四个 X 向量在 495、496、502、503 行加载，分别落入 z5/z4/z6/z3。X0 使用当前 x3，X1 用 panel_stride 的缩放寄存器索引，X2/X3 的地址通过 500–501 行两条 add 构造。另两条 add 为 494 行推进 L 当前列一个 double，以及 504 行推进 X0 一个 `ldx*sizeof(double)`。四个面板并没有作为四条独立指针每 k 各做一次自增。

505–520 行每个 L 系数供四条 FMA 消费：第 0 行累加器为 z31/z30/z29/z28，第 1 行为 z27/z26/z25/z24，第 2 行为 z23/z22/z21/z20，第 3 行为 z19/z18/z17/z16。编译器在不同输出之间调整了指令排列，例如某行第三组 FMA 先于第一组；各输出自己的递增 k 累加链保持独立，没有对同一输出重排 k 或拆成多条部分和。

## 入口、栈与最终 C 回写

T13 在 459–486 行完成正 count 路径的面板/行偏移准备、边界判断、16 条累加器置零和 predicate 设置，共 28 条指令。新核整个函数没有 `sp` 访问，没有 `stp/ldp` 寄存器保存，也没有 `bl/blr`；栈帧为 0 字节。入口的八个参数均通过通用寄存器传递。无热 spill 的结论同时覆盖 L 系数、X 和累加器。

T8 正 count 入口 147–221 行有 62 条实际指令，其中包括六次保存寄存器对；147 行建立 96 字节栈帧。276–288 行恢复 x19–x28，357 行恢复 x29/x30。其热循环也没有 spill 或核内调用，不能把 T8 函数入口的 ABI 保存当作每 k 的临时值溢出。

T13 的 C 读/减/写只在热循环结束后的 `.L24` 发生。524–600 行为 77 条实际指令，601 行单独 return；T8 对应 292–356 行为 65 条指令，不含其寄存器恢复及 return。

|C 回写区间项目|T8 16×8|T13 4×32|
|---|---:|---:|
|C `ld1d`|16|16|
|`fsub`|16|16|
|C `st1d`|16|16|
|地址 `add`|15|24|
|`sbfiz`|1|2|
|`smull` / `mov`|0 / 0|1 / 1|
|`ptrue`|1|1|
|区间指令合计|65|77|

每条累加链初值为零，循环末尾才将原 C 装载、单次相减、写回；没有先装 C 进行负 FMA，没有额外 FMA 或除法。count≤0 分支 604–620 行将 16 条和置零后跳到同一 C 回写区，因此仍遵循原 C−0 语义。

## 等输出的载入和调用比较

在实际 VL 为八个 double 时，每 128 输出、每 k，T8 读取 16 个 L double 加一个 64 字节 X 向量，架构加载有效载荷为 `128+64=192` 字节；T13 为四个 L double 加四个 X 向量，即 `32+256=288` 字节。T13 的 L 读取减少，但总输入有效载荷增加 50%。这里统计架构加载操作，不表示 DRAM 总线流量或缓存 miss。

完整 16×32 区域双方都调用四次核：T8 覆盖四个 16×8 列段，T13 覆盖四个 4×32 行段。每 k 都是 64 条向量 FMA；热循环静态指令合计分别为 208 和 136，输入有效载荷分别为 768 和 1152 字节。不能用新核一次调用对照旧核多次调用来声明收益。T13 外层在 2469/2479/2489/2499 行确有连续四次 `update4x32_sve` 调用；本报告的微核叶函数结论不覆盖调用方参数准备、活跃值保存或整体 OpenMP 任务开销。

r8 的历史 T11 8×16 报告曾记录每 k 8 个 L 读取、2 个 X 加载、16 FMA、39 条热循环指令和无热 spill；该数字来自 r8 独立生成对象，本轮未对 T11 重新生成或作同时性能比较。相对该历史形状，T13 的 L 读取减半、X 加载翻倍是可见的形状差异，不能由 39→34 推定周期数或整算子收益。

## 结论范围

实际代码生成兑现了四路 RHS 之间复用 L 的源码假设，没有新增微核栈访问或调用；代价包括四路 X 加载及更复杂的 C 回写地址组织。没有发现明显的微核代码生成错误。本文不测量缓存、吞吐、调用点成本或完整算子性能；正确性、三轮官方测量与是否晋级仍应由 r10 的实际预检和登记比较决定。
