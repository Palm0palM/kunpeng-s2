# r10 准备阶段审查

本轮从已完成的 r9 私有控制脚本派生，只比较 T8-control12 的同源码新 run 与 T13-sve4x32。T8 原台账及历次证据保留，记录时使用 --repeat-existing；T13 父版本仍为当前最佳 T8-control12。

预先固定每成员一套完整官方预热，随后三套正式用例依次 A/B、B/A、A/B。预热单独保存，不进入正式比较；保留全部正式样本。TEST_RUNS=3，原 benchmark、runner、容差、38 CPU 单 NUMA、24GiB、1800 秒限制不变。真实 KML25.1/GCC12 与指定 KML25.2 的差异继续明确记录。

调度提交仍先冻结 payload，再保存唯一 job ID；不重试不确定提交。远端计算前必须通过 Linux aarch64、38 CPU 单 NUMA 检查。参考库探测、各成员通用预检，以及 T13 的 4×32 补充预检全部成功后才预热和测量。取回和登记仍要求调度器 SUCCEEDED、进程退出 0、全部预期官方 PASS、每套真实 KML/OpenMP 链接记录。

T13 独立只读审查未发现具体缺陷：四面板地址与 packed/strided 步长一致，16/8/4 行调用分别覆盖 4/2/1 个不重叠行块；列循环受当前 CT 末端 je 限制，余列连续处理；不足四行保持原路径。每个输出保持从零开始的递增 k FMA 链及末尾一次 C−sum。新核受每个线程自身的 SVE/VL=8 保护。

这里只记录静态审查。题目编译、实际正确性、目标汇编和性能结果必须来自之后的调度计算节点。没有在本机运行题目或计算、验证哈希。
