# C27-row3staged：18 累加器的逐向量调度约束

- 父候选：C25-row3x6；本轮测量基线与成绩由根代理统一登记。
- 状态：prepared，尚未对 C27 编译、做正确性检查或测量性能。所有验证仅在超算调度分配的计算节点进行。
- 单一假设：GCC 对 C25 的三行双列共享循环按整行 a→b→c 重排，使多个原始/移位输入窗口长时间存活；逐向量消费更新结果并阻止后续新加载跨越边界，可能降低输入临时量的寄存器压力。

## 已有依据

C25 的远程 GCC 10.3.1 汇编位于 ../C25-row3x6/sve-correctness-sep11c/raw/conv2d-sve.s。主循环 .L283 中，第三输出行第 5 个向量 c4 溢出到 sp+912：3624/3631 行生成 v4*ck0 和 x4*ck1，3633–3636 行读槽、顺序加两次并写回；4187–4193 行最终从槽读取并存储 dst2+i+4*lanes。此观察只描述 C25；不预判 C27 的汇编或速度。

## 唯一改动

仅在 conv_sve_rowtriple 的 t=2..kh-1、ik 每次推进 2 的共享循环中，完成向量下标 0、1、2、3、4 的 aN/bN/cN 两次更新之后，各加入一个空的 GNU volatile asm。asm 以 w 约束消费对应三个已更新 SVE 向量，并声明 memory clobber。下一个新窗口加载位于该屏障之后；第 5 个向量是末组，不再添加屏障。

18 个累加器、每输出 kernel 行/列顺序、独立 svmul/svadd、循环边界、输入偏移、最终安全移位加载、尾部和小核回退均沿用 C25。其他 helpers、非 SVE 路径、OMP 调度、README、benchmark 和 run.sh 均不改。

## 静态范围与语义审查

新增 asm 没有汇编指令、输出操作数或真实内存读写，仅增加编译器依赖和内存调度约束；不改变输入访问范围或运算次数。aN/bN/cN 的值在屏障前已经按原顺序完成更新，屏障只读取它们。全部原有指针偏移与输出地址保持不变，故边界证明继承 C25。w 约束位于已有 AArch64 SVE target helper 内；其他平台预处理分支不增加新 asm。

## 风险与待验证事项

空 asm 本身不发指令，但编译器可能增加寄存器搬运、同时保留更多系数，或因调度自由降低而增加停顿；memory clobber 也可能妨碍加载与计算重叠。它不保证消除 c4 或其他累加器的 spill，也不保证提速。C 作用域本身不能防止优化器重排，故本候选使用显式约束。
