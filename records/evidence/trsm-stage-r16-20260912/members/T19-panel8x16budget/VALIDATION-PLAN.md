# T19 待执行验证

全部编译、题目执行和汇编生成仅在调度分配的计算节点。以下是计划，不是通过声明。实际使用 GCC12.3.1 / KML25.1、38 CPU 单 NUMA；不得描述为指定 KML25.2 复验。

## 新微核直接检查

固定 API：`solve8x16_panel_sve(int start,int lda,const double *L,double *x0,double *x1)`。每个面板行步长 RHS8，当前八行起点 start，L 已偏移到当前行块且仍从原列零寻址。直接调用必须先确认实际 VL8。

运行前联合预检方案固定为 18 案例：start=0/1/7/8/9/15/16/255/256，各配 lda padding=1/7。这替代作者初稿的“至少28例”建议；保留正负系数与不同面板数据，增加对8行及256历史边界两侧的明确观察，不把未执行的初稿数量记为通过。以显式逐 k `fma()`、逐 q 前代、最后单次减法与普通除法的标量参考做逐位核对，不能仅依赖官方容差。应覆盖正负系数、消去、非单位对角、不同 lda、两组不同 RHS、独立两面板 guard、目标八行之外的 X 不变、L 全部字节不变。参考不得重复调用被测核。

检查十六个输出向量各自只有一条按全局 k 递增的 FMA 链。对每个调用实际观察 start、lda、L 行首、x0/x1 与 worker scratch 的关系；要求 x1=x0+m*8，两者行零原点及 RHS8 步长，不接受把第二面板写成 x0+8。

## 分派、分配与整算子

保留原 r14 通用预算和大路径 wide32 的全部覆盖，新增专用 panel8x16 预检；旧通用 parser 必须适配超预算路径的实际 X 分配字节与旧/新核入口，不能用旧期望掩盖错误。仅预检临时副本允许注入只读入口/参数/分配观察，原候选、官方计时和目标汇编使用未插桩源码。

必须实际观察 wrapper 入口、新旧微核入口、shared-history 分配调用及每 worker X 分配。对于安全超预算、正常 HWCAP、scratch 成功且 VL8 的调用：

- wrapper=1；history 分配调用=0；每 worker 的 X 请求为 m*128 字节。
- new entry=`floor(n/16)*floor(m/8)`。
- old entry=`ceil((n%16)/8)*floor(m/16)`；packed-L entry=0。

必须覆盖预算边界 1039/1040/1041、八行尾边界、n=1/7/8/9/15/16/17/31/32/33 等宽度，任意合法 lda/ldb padding、L 不变和 B/面板 guards。至少 1/4 线程及一组 38 线程；需有正常完整十六列任务，也需有不足十六列的最后任务。4095×9 只能证明 wrapper/旧尾核，不能证明新微核；固定1039/1040×15/16/17/31/32/33网格，并在正常38线程过程增加1047×33，实际覆盖新核后的NEON4行与标量3行尾以及一列尾；仅有1041×9/4095×9不足以覆盖该分支。m>4096 的大路径案例继续检验继承的大更新，不能替代新小路径覆盖。

分别注入：预算内 shared-history 失败、超预算 worker scratch 失败、无 SVE 与实际窄 VL。预算内 shared 失败必须保持原小路径而不进入 wrapper；无 SVE 不进入 wrapper且保持原 m*64 字节 X 请求；窄 VL 在安全超预算时仍进入 wrapper且请求 m*128 字节，但新/旧 SVE panel 核入口均零。scratch 失败时 wrapper 仍进入，但该 worker 的全部有效列由其自身 direct fallback 处理，新/旧核不应被假计数。fixture 分配必须排除在观察器之外。

大路径继续完整 CT64 wide32 预检（28 direct、28 whole、56 参数观察、7 tile 进程）及原官方套件。实际入口次数和分配统计须由严格解析器核对，不能只检查输出 PASS 或新核入口零次。
