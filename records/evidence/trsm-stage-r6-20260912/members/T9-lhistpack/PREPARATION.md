# T9-lhistpack：小路径共享打包 16 行块的 L 历史系数

2026-09-12 从 `.runs/trsm/T8-svepanel16/source/` 复制五份源文件，只有 `trsm.c` 改动。T8-svepanel16 是当前最佳；其 KML 25.1.0 / GCC 12 三轮同分配比较及 ZIP 验证已完成。T9 目前只完成代码准备与静态检查，尚未编译、运行、做数值验证或取得性能结果，未登记或晋级。

用户最新约束覆盖旧文档中的本机运行及哈希留痕要求：不计算或验证任何哈希；编译、正确性测试、sanitizer、benchmark 和汇编生成全部留给超算调度分配的计算节点。本候选未调用会内置计算哈希的实验工具。参考环境 KML 25.1.0 不等同题目指定的 KML 25.2.0。

## 单一假设

T8 的实际 GCC 12 SVE16 历史 k 热循环有 52 条指令：16 次 FMA、16 次系数广播加载、1 次 X 加载、17 次地址 add 及循环控制，无热循环 spill。候选把小路径所有完整 16 行块的历史 L 系数一次打包成 k-major 连续布局，供所有 RHS 面板共享，期望减少每个 k 的分散行地址运算和行访问流。这是待验证假设，不是性能结论。

新共享副本需要 O(m²) 复制、额外存储和一次打包阶段的 barrier；按块静态分工的工作量随块号增长，可能有负载不均。这些成本与分配、释放均在 `l_trsm` 内，完整计入原有算子计时。没有按官方精确尺寸分派，也没有增加调优参数。

## 布局与微核接口

令完整块数 `B=floor(m/16)`，完整块号 `b=0..B-1`，本块首行为 `start=16*b`。只存历史部分 `k<start`，本块内部系数和对角元继续读取原 L。

```text
offset(b) = 128*b*(b-1) doubles，b>=1
packed_history[offset(b)+k*16+r] = L[(16*b+r)*lda+k]
其中 k=0..16*b-1，r=0..15
total = 128*B*(B-1) doubles
```

块 b 长度为 `256*b` 个 double；`offset(b+1)-offset(b)=256*b`。最后块结束位置等于 `offset(B)=total`，所以各块无重叠、无缺口。第零块无历史项，不占空间，继续调用原 T8 微核。

原函数 `solve16x8_panel_sve` 原样保留。新函数完整签名为：

```c
static void solve16x8_panel_packedL_sve(int start,int lda,const double *L,double *x,
                                         const double *packed_history);
```

- `L` 指向本 16 行块第一行的原列零；`x` 保留 RHS 打包面板的原行零。
- `packed_history` 指向本块的历史基址，微核直接读取 `packed_history[(size_t)k*16+r]`。
- 新核只替换历史 k 循环的 16 个系数读取。每条累加链仍按递增 k 累计；块内递增 q 的 FMA、单次减法、对角除法、X 写回与 T8 原函数保持相同。

## 分配、同步与回退

`solve_panel` 在 `TRSM_CAN_DISPATCH_SVE` 编译保护内，仅当 `HWCAP_SVE` 存在且 `full_blocks=m/16>=2` 时尝试共享分配。先保护 `blocks*(blocks-1)` 的 `size_t` 乘法，再保护它乘 `128*sizeof(double)` 的字节数转换。保护不通过或 `posix_memalign` 失败均保留空指针，使用 T8 原路径。

满足上述条件时，共享分配是进入并行区前的第一个 `posix_memalign`。复用原来的单个 `omp parallel`：所有 worker 在共享指针非空时先执行同一个 `omp for schedule(static)`，按 `b=1..B-1` 分工打包。循环保留隐式 barrier，之后每个 worker 才检查 `have_sve && trsm_sve_has_eight_doubles()`、分配自身 X 并执行原 RHS 面板循环。打包条件不依赖线程自己的 VL 或 X 分配结果，因此所有 worker 都参与同一 barrier，X 分配失败也无法跳过它。共享区在整个 parallel 结束后释放。

- 当前 worker 只有 `svcntd()==8` 时才进入任一 SVE16 微核。共享区成功且 `first_row>0` 时调用新核；首块和共享区失败时调用旧核。
- 无 SVE 或当前 worker VL 不是 8 个 double 时，从第零行使用原 NEON/标量路径。窄 VL 下可能创建未使用的共享区，这是当前统一的 HWCAP 分配条件，不改变回退计算。
- 任一 worker 的 X 分配失败时，仍执行原标量前代。该 worker 可以已经参与共享打包，不影响其他 worker。
- `m<32` 不申请共享历史区；`m<16` 不进入 SVE16 微核。完整 16 行前缀后的 1..15 行由原 NEON4/标量尾部覆盖，未被打包。
- 仅在共享指针非空且块号非零时形成块历史指针；不存在对空指针做 pointer arithmetic，也不存在 `b=0` 的无符号减一。
- X 的 RHS 尾列继续补零，B 只写回有效列；L 只读。`lda`、`ldb` 与原逻辑相同，padding 不参与新打包。

大工作集路径、KB=256、CT=64、64 MiB 算法选择预算、原 NEON 尾核和精度设置不变。`bench_trsm.c`、`run.sh`、`README.md`、`compat/kblas.h` 从 T8 原样复制。

## 后续超算预检与比较

1. 原 r5 入口仪器只识别 `solve16x8_panel_sve`；必须同时识别新核，分别记录新/旧入口并检查合计。正常 SVE8 且所有分配成功时，每个 RHS 面板的新核调用数为 `max(floor(m/16)-1,0)`，旧核调用数在 `m>=16` 时为 1；合计与 T8 的完整 16 行块数一致。
2. 对新核做独立微核验证：包含 start=0、非 16 倍数的历史长度和块边界；显式构建 `packed[k*16+r]`，用保持递增 k/q 的 FMA 参考，检查历史前缀 X、后缀保护区、L 与 packed 历史只读。调用前需满足目标 SVE / 8 double guard。整算子实际仅以 16 的倍数 start 调用新核。
3. 整算子覆盖 `m=1/3/4/5/15/16/17/31/32/33/47/48/49/63/64/65/255/256/257` 及尾部 1..15 行、窄 RHS、独立 `lda=m+3` / `ldb=n+7`，检查有限值、误差、残差、L 不变与 B padding。保持原 4095/4096/4097 算法边界和非正维度无操作验证。
4. 强制全部分配失败、无 SVE 和每个 worker 窄 VL 回退。额外必须覆盖**仅第一次共享 history 分配返回 ENOMEM、后续 X 分配成功**：使用 m>=32 的小路径输入，确认新核入口为零、旧核合计等于完整块数、数值及保护区正常；此模式与全部分配失败走标量是两种不同的覆盖。
5. 在同一 38 核单 NUMA 分配内，以当前最佳 T8 原样快照为对照，与 T9 交错各跑三轮完整官方套件，`TEST_RUNS=3`，GCC 12 与 KML 25.1.0 的编译、链接、实际运行库及绑定一致。保留逐轮逐用例平均耗时，再比较跨轮中位数、波动和各用例退化；不能以旧 T7 或不同参考环境替代本轮 T8 对照。
6. 保存目标汇编，检查新历史 k 热循环的地址指令、广播、FMA、spill 与函数开销。以包括共享打包/分配/同步的完整算子耗时判断收益；未满足正确性和同环境稳定改善前继续使用 T8。若指定 KML 25.2.0 可用，单独复验并记录，不能把 25.1.0 写成指定环境。
