# T9-neondirect：小工作集 NEON 前代直接使用累加器

2026-09-12 准备，来源为 `.runs/trsm/T7-diagpanel/source/`，仅修改候选 `source/trsm.c`。这是待测候选，没有登记性能、晋级或发布；不包含 T8 的改动。本机只做源码编辑与静态差异检查，没有编译、正确性测试、sanitizer、benchmark 或哈希操作。

独立静态审查已完成，未发现明显源码问题；尚未在目标计算节点编译或测试。静态审查不代表正确性或性能通过。

单一假设：父任务在超算 GCC 12.3.1 汇编中观察到小路径每个完整四行块的 `sums[32]` 清零、写出和重读，而历史 k 热循环没有 spill。将累加与块内前代放入同一个 NEON 微核，可能使编译器直接沿用累加寄存器，减少块间临时内存访问。这是编译和性能方面的待验证假设；源码没有数组不保证机器码没有寄存器 spill。

## 实现范围

- 新增 `panel_solve4x8_neon(start, lda, L, x)`，仅在 AArch64 小工作集 `solve_panel` 的 `h == ROWS` 分支调用。L 指向当前四行的起始位置，列索引仍以全局 start 为基准，X 仍是每线程 `m × 8` 打包面板。
- 历史 `k < start` 部分保留原 `panel_sums` 的 16 个 NEON 累加器、递增 k 顺序以及每个向量的显式 `vfmaq_n_f64` 链。每行八列由四个双精度向量覆盖。
- 四行依次求解；每行内部 q 从 0 递增到 r−1，每个贡献先 `vmulq_n_f64` 再 `vaddq_f64`，保留非融合乘加的中间舍入。随后分别减去累加值、除以对角元，结果写回同一 X 行。已解行覆盖原累加器变量，供后续 q 使用。没有增加倒数近似、重排 q 或放宽编译浮点设置。
- `run.sh` 原有 `-ffp-contract=off` 保持不变。远程汇编仍需确认 q 使用独立 `fmul` 和 `fadd`，没有被合成为 `fmla`；历史 k 则应继续使用 `fmla`。
- 尾部 1–3 行保持原 scalar/omp-simd 累加与求解，非 AArch64 路径也保持原逻辑。右端项尾列补零、逐线程分配及分配失败回退、最终写回、线程与调度均不变。
- 原 `panel_sums` 不变，继续供 T7 大工作集对角块使用。全部大路径、SVE 更新与安全分派、KB/CT、64 MiB 算法选择预算不变；没有按官方精确尺寸分派。
- 五个原始源文件直接复制；`bench_trsm.c`、`run.sh`、`README.md` 与 `compat/kblas.h` 没有编辑。
