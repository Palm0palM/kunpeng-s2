# T9-lhistpack 实际目标汇编审查

2026-09-12。仅只读分析已取回的目标汇编：T9 来自作业 1579365 的 `assembly-review-inputs/T9-lhistpack.s`；T8 对照为 `../optimization-20260912-r6/diagnostics/preflight-results/T8-control12/trsm-panel16.s`。本文行号均为相应 `.s` 文件的一基行号。没有编译、执行、联网、计算哈希或重新验证源码身份。

**结论：连续历史布局确实减少地址运算，但新核出现每个 k 一次整 Z 向量的系数 spill/reload。** 不能用静态指令数下降推断提速；共享打包和同步也有真实生成代码开销。

## 历史 k 热循环

|每个 k 的实际指令|T8 `.L25`，531–582 行|T9 packed 核 `.L31`，1083–1122 行|
|---|---:|---:|
|`ld1rd` 系数广播|16|16|
|`ld1d` X 向量加载|1|1|
|`fmla`|16|16|
|`add`|17|3|
|整 Z 栈写 `str z`|0|1|
|整 Z 栈读 `ldr z`|0|1|
|`cmp` / `bne`|1 / 1|1 / 1|
|总指令数|52|40|

T8 的 16 个行地址分别由 add 形成，另一次 add 推进 k。T9 的 16 个系数来自同一个 x4 基址的常量偏移 0..120；1100 行将 packed 地址推进 128 字节，1103 行将 X 地址推进 64 字节。第三个 add 是 1085 行的 `x7=sp+112`，用于新增 spill 槽。

新增热 spill 的完整证据：1084 行把 packed+120 的第 15 行系数广播到 z0；1101 行 `str z0,[x7]` 保存它；1102 行复用 z0 加载 X；1105 行 `ldr z8,[x7]` 取回该系数；1120 行完成第 15 行累加。它保存的是广播系数，16 条累加链仍留在 Z 寄存器里。有效 VL=8 double 时，每个 k 多出 64 字节栈写与 64 字节栈读；这是栈访问流量，不应等同为内存总线流量或固定周期惩罚。

新核在 1083–1099 行先安排全部 16 个广播，再加载 X，扩大了系数同时存活范围；实际可见结果是一个系数落栈。历史循环内没有 `bl`/`blr`，T8 和新核的整个函数内也没有调用。

新核 1035–1037 行申请 `112+1*VL_bytes` 栈帧，在 VL=64 字节时为 176 字节；1039–1048 行保存 ABI 寄存器，1512–1535 行恢复。该 ABI 保存/恢复与上述每 k 的整 Z spill 是不同成本。T8 在 459 行申请 160 字节栈帧，历史热循环无栈访问。

## 块内 q 前代

T8 从 `.L24`（589 行）进入展开求解；T9 从 `.L30`（1123 行）进入。只统计计算主体，二者均有：

- 136 次 `ld1rd`，对应 120 个块内严格下三角系数和 16 个对角元。
- 120 次融合乘加：T8 为 22 `fmla` + 98 `fmad`，T9 为 26 `fmla` + 94 `fmad`。
- 16 次 X 加载、16 次减法、16 次除法、16 次 X 写回。

T9 的 q 段在 1124–1188 行由原 L 参数 x2、lda 和 start 形成各行指针；不再从 packed-history 指针取块内系数。首行在 1131–1141 行完成 B-sum、除对角和写回；下一行在 1157–1178 行依赖该已解向量，再做减法和除法。最后一行在 1484–1508 行串接延后的依赖 FMA，1509–1511 行最终减法、除法和写回。计算主体中未见额外的整 Z spill 或函数调用。

生成代码保留了 16 行展开前代的运算结构和依赖顺序，寄存器分配与独立指令调度发生变化。上述结构及数量核对不是独立数值正确性证明；最终仍以实际微核、算子及官方容差测试为准。

## 共享打包与分派的可见成本

`l_trsm` 的小路径 `.L520`（5070 行）在 5084–5090 行检查 HWCAP 与 m>=32，5093–5097 行计算 `B*(B-1)<<10` 字节并执行共享 `posix_memalign(...,64,bytes)`。失败进入 `.L523`，共享指针保持零。5113 行调用原单个 `GOMP_parallel`，返回后 5115 行释放共享缓冲区。

worker 在 1603 行检查共享指针；成功时 1604–1618 行读取线程数/线程 ID，并用除法和余数均分 B-1 个块，`.L91`（2458 行）处理余数分配。分配的是块数，块号越大历史复制量越多，因此仍存在打包负载不均的可能。

实际打包是**标量复制**：块设置 `.L95`（2353 行）计算 `b*(b-1)<<10` 及各 L 行地址；内层 `.L97`（2408 行）每个历史 k 有 16 次 `ldr d0` 和 16 次 `str d0`，r 循环被完全展开，没有 NEON 向量搬运或 SVE gather。每个 k 读取并写出各 128 字节，目的地址前进 128 字节，源列地址前进 8 字节。这份 O(m²) 复制由全部 RHS 面板共享，但其成本没有消失。

打包结束经 `.L98` 到 `.L96`，1620 行调用新增的 `GOMP_barrier`；无共享缓冲区时直接跳到 `.L93`。每 worker 的 VL 检查在 1624 行，X 分配在 1633 行，因此窄 VL worker 也会先参与共享打包，X 分配失败不会跳过打包 barrier。原求解结束 barrier 仍在 2070 行，2092 行尾调用 `free(X)`。

`.L50` 的 2253–2261 行检查首块和共享空指针：任一成立则进入 `.L147`，2244 行调用旧核；否则 2267 行形成历史块地址，2268 行调用 packed 核。剩余行经 `.L159`（2274 行）转原尾部路径。共享打包并未消除每 16 行块的微核调用开销。

## 判断范围

本审查支持“地址 add 减少，同时出现热循环系数 spill”的代码生成结论，并确认复制、分配、barrier 和释放仍在算子内。它不提供缓存命中率、spill 的实际停顿、带宽、线程不均程度或完整算子耗时，不能宣称候选更快或更慢。最终保留/晋级判断应基于当前 T8 与 T9 同分配三轮完整测量及实际正确性结果。
