# Package static review

Prepared using only text/file operations. No C compiler, operator, diagnostic binary, sanitizer, benchmark, SSH or scheduler command has been run for this package.

- The production `conv2d.c` copy is byte-identical to prepared C40. Its separate full executable and assembly are built without `-finstrument-functions`; the instrumented executable includes the same untouched source in a separate translation unit.
- The original C37 sample generation, read-only input/kernel setup, allocation-edge guards, poison/canary checking, strict scalar accumulation and `memcmp` result comparison are retained. The shared case routine selects a call target; it defaults to public `conv2d`. Only the independent instrumentation main changes it to the direct wrapper, after preceding calls and teams have joined.
- The full matrix has four disjoint families: 2,808 + 144 + 576 + 32 = 3,560. No hardcoded official-shape dispatch is introduced. The larger 81×81 case is reference verification of long ordered loops, not a timing case.
- The direct wrapper accepts only `kh=1..5` and `oh=6/24`. It computes global input/output strides as `size_t`, uses `groups=oh/6`, and assigns six disjoint output rows to each group. Every pointer passed to the helper denotes a present row. The last needed input row is output row `oh-1` plus `kh-1`, exactly `height-1`.
- Entry counters and worker masks use relaxed atomics. Reads/reset occur after joins; relaxed ordering suffices for the counters because OpenMP completion separates the phases. Instrument callbacks are not instrumented and never call the operator. Per-case rowsix expectations reject accidental public entry for `kh=5`, missing entry for `kh>=6`, extra recursion and omitted direct fallback calls.
- The expected worker mask is formed only after the shared setup verifies that the actual and requested team sizes agree and equal 1 or 4. The direct and public phases both include 24-row cases; four complete six-row tasks reach four workers under the unchanged static scheduling setup.
- The copied runtime VL setup verifies the initial thread and every OpenMP worker for 16/32/64 vector bytes. Runtime widths use those verified lane counts, not an assumed 512-bit width.
- Public full tests cover `oh=1..12`, all six-row remainders, exact six/twelve rows and 24 rows; `kh=5/6/7`, `kw=1/2/3`, smaller kernels, `3L/6L` transitions and width 1. Instrumented entry counts and source branch conditions complement these cases; they do not claim direct machine basic-block counting.
- Remote wrapper checks allocation before compilation; compiler mismatch fails before the diagnostic executables run. Pipeline failure, shape/reference/guard error, count/entry/mask mismatch or log-writer error returns nonzero. A later driver must preserve a unique job ID and must not mark missing or partially fetched logs as complete.

No blocking static issue was found. Runtime compilation, strict bitwise correctness, actual instrumentation behavior, requested hardware VL support and emitted production assembly remain unverified. The exact matrix and acceptance requirements are in `README.md` and `validation.json`.
