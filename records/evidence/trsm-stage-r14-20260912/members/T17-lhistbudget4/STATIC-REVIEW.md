# T17-lhistbudget4 独立静态审查

2026-09-12，只读审查已准备的五文件 source，对照 T10-lhistbarrier 与当前 trsm 官方 runner/benchmark 文件。**未发现本次预算改动的阻塞问题；尚未编译、执行或验证性能。** 本报告只根据源码与轻量文本/字节比较，不读取仍在编写的预检，不计算或验证哈希。

## 变更范围

`source/trsm.c` 相对 T10 只有两个相连的策略改动：560–561 行增加说明与 4MiB 命名常量，578–581 行在原 `posix_memalign` 外增加 `bytes <= TRSM_PACKED_HISTORY_BUDGET_BYTES` 条件。删除这两处新增文本并还原原分配语句后，整个文件与 T10 相同。677 行 KB256/CT64 起的大路径后缀未变，生产循环 592 行仍为 `schedule(static)`，没有合入 T14。

bench_trsm.c、run.sh、compat/kblas.h、README.md 四文件与 T10 的对应文件逐字节相同；前三份也与当前 trsm/ 对应官方控制文件相同。未修改官方用例、精度或线程设置。

## 预算与整数安全

565 行先拒绝非正 m/n。568–569 行计算完整 16 行块数并把共享指针初始化为 NULL。572 行 `full_blocks>=2` 确保后续 `blocks-1` 非零；574 行先证明 `blocks*(blocks-1)` 可表示，576 行再证明乘 `128*sizeof(double)` 可表示，577 行才实际求 bytes。预算比较使用已经安全算出的 bytes，没有提前做可能溢出的乘法；4*1024*1024 在目标 GCC 的 int 范围内。

令 b=floor(m/16)，本实现共享副本字节数为 `1024*b*(b-1)`，预算为 4,194,304 字节。它计量实际共享 L 历史副本，不是完整三角 L，也不包括原 L/B、每线程 X、分配器开销或硬件缓存容量。

| m | b | 共享副本 bytes | 预算允许尝试 |
|---|---:|---:|---|
| 32 | 2 | 2,048 | 是 |
| 512 | 32 | 1,015,808 | 是 |
| 1023 | 63 | 3,999,744 | 是 |
| 1024–1039 | 64 | 4,128,768 | 是 |
| 1040–1055 | 65 | 4,259,840 | 否 |
| 2432 | 152 | 23,502,848 | 否 |

因此在原小路径、m/n 合法且检测到 SVE 的前提下，m=32..1039 可尝试共享分配，1040 起超预算；m<32 没有共享历史分配。m=1024 不是拒绝点。一般 n、lda/ldb 和不足 16 行的尾部不改变这项副本预算，没有官方尺寸等值分支。完整算法仍由 1040–1047 行原 64MiB 三角工作集规则选择。

## 共享状态、边界和回退

分配发生在 586 行并行区之前，packed_history 是所有 worker 共享的变量，进入并行区后不会重新赋值。超预算、整数保护拒绝或分配失败都保持同一 NULL；所有线程一致跳过 591–601 行生产区及其隐式 barrier，不会出现部分线程进入 barrier。预算内成功则所有 worker 进入原 omp-for，完整保留生产完成后的隐式 barrier。

生产 block b 的写区间从 `128*b*(b-1)` 开始，长度 `256*b` 个 double；终点恰为下一 block 的前缀，互不重叠，最终不超过已保护的分配总量。分配、布局、系数读取、原 packed 核和算术均未改。

624–632 行只有共享指针非 NULL 且 first_row 非零才进入 packed 核。NULL 时完整行块自然调用原 solve16x8_panel_sve；首块、不足 16 行尾部和 RHS 列填充/回写不变。每线程 X 分配失败仍在 609–615 行使用原 B 上标量前代，没有新增提前离开生产 barrier 的路径。668 行在并行区完成后释放共享指针，free(NULL) 保持合法。

非 SVE 编译文本路径中，常量、指针声明、分配、生产、消费判断及 free 均处于 TRSM_CAN_DISPATCH_SVE 条件内；前向声明/定义也一致受保护。AArch64 非 SVE 路径保留 NEON，非 AArch64 保留标量路径，没有新增对不可见常量或指针的引用。运行时仍先查 HWCAP，再逐线程检查 svcntd()==8。预算内且硬件有 SVE 时，即使 worker 的实际 VL 不为 8，原共享打包仍可能发生，之后自然使用非 SVE 消费；这是继承行为，不应把预算条件误称为逐线程 VL 条件。
