# T10-lhistbarrier：限制 packed-L 历史循环的系数存活范围

2026-09-12 从 `.runs/trsm/T9-lhistpack/source/` 复制原五份源文件。只修改新目录 `trsm.c` 的 `solve16x8_panel_packedL_sve` 历史 k 循环，在第 4、8、12 条 FMA 后分别增加一处 GNU empty volatile asm，共三处。没有提交新作业、编译、运行、登记或晋级；本机只做轻量编辑和静态检查，不计算或验证哈希，不使用额度重置卡。

## 来源与单一假设

T9-lhistpack 的 r6 正式比较未晋级：同分配三轮合计中位数 474.48 ms，对照 T8 为 452.02 ms，慢 4.97%；中用例 267.33 vs 239.25 ms，慢 11.74%。T8 仍是当前最佳。T9 小用例改善不能抵消其中用例退化，也不能据此将共享打包方案视为已成功。

实际作业 1579365 的 T9 目标汇编中，packed 核 `.L31` 每 k 为 40 条指令，包含 16 次系数广播、16 次 FMA，以及一次整 Z 系数 spill/reload。它在 1083–1099 行安排全部 16 个广播，1101 行把第 15 行广播系数写入栈，1105 行取回；VL=8 double 时各为 64 字节。16 条累加链没有落栈。该观察说明存在可针对的寄存器压力，但不能证明它解释了 T9 的全部退化。

T10 只检验一个假设：在每四条 FMA 后设置编译器约束，让刚更新的四个累加器必须先成为 asm 输入/输出，并用 memory clobber 阻止后续系数加载整体越过边界，避免同时保留 16 个广播值，尝试去掉已观察到的历史热循环系数 spill。

## 精确改动

```c
/* a0..a3 的历史 FMA 后 */
__asm__ __volatile__("" : "+w"(a0), "+w"(a1), "+w"(a2), "+w"(a3) : : "memory");
/* a4..a7 的历史 FMA 后 */
__asm__ __volatile__("" : "+w"(a4), "+w"(a5), "+w"(a6), "+w"(a7) : : "memory");
/* a8..a11 的历史 FMA 后 */
__asm__ __volatile__("" : "+w"(a8), "+w"(a9), "+w"(a10), "+w"(a11) : : "memory");
```

每处都是空模板，四个操作数使用 `+w` read/write 约束；没有输入操作数列表内容，clobber 列表只有 `memory`。它们处于已有的 Linux aarch64 GCC SVE 编译保护及函数 target 属性下。每组累加器输入建立前一组 FMA 到 asm 的数据依赖；memory clobber 约束编译器对边界前后内存访问的移动。空 asm 本身不执行算术，也不是 CPU 内存屏障，实际指令选择、调度及是否消除 spill 必须看目标 GCC 12 的输出。

没有在第 16 条 FMA 后增加第四处 asm，没有改变递增 k 次序、FMA 表达式、X 加载或系数索引。原 T8 回退微核、packed 布局、分配/释放、HWCAP/VL 分派、m 阈值、共享 pack 与 barrier、q 前代、NEON 尾部、大路径、KB/CT、64 MiB 预算和全部精度条件不变；没有组合另一种预算分派或调优策略。

## 静态检查范围与限制

已核对三处 asm 的分组分别为 a0..a3、a4..a7、a8..a11，输出都是 `+w`，每处都有 memory clobber。文本差异只包括这三处及说明注释；四份非算子文件保持原样。未发现该 GNU asm 形式在源码层面的明显矛盾，但尚未在指定目标 GCC 12 上确认 `svfloat64_t` 操作数的约束接受情况，不能把静态检查写成编译通过或数值通过。

`+w` 将累加器约束在寄存器中，memory clobber 也可能限制有益的加载调度，带来别的寄存器分配或吞吐代价。消除一个已知 spill 并不保证整算子更快；共享打包自身的复制、缓存和同步成本仍完整保留。
