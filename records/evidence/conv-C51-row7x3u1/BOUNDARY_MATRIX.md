# C51 建议边界矩阵（未执行、未创建诊断包）

建议延续既有只读 input/kernel、两侧 guard、padding canary、poisoned output、逐位 scalar 参考检查。以真实 SVE 长度 16/32/64 字节、线程 1/4 形成六配置；每配置须检查所有 worker 实际 VL/线程数。这里 L=svcntw()，pad 和 leading 各取 0/1 的四组合；实际输入尺寸由 ih=oh+kh−1、iw=ow+kw−1 得到。所有范围均须在超算计算节点执行，不能在本机替代。

5648 仅为此建议集合的算术计数，不是实测通过数。oh=1..15 覆盖低于七行阈值、阈值两侧和所有余数 0..6；oh=28 提供至少四个完整七行组。kh=6/7/8 覆盖公共回退、共享阶段单次和重复，较大 kh 检查多轮共享/收尾。低向量边界补足原 quad/triple/pair/prefix 的列尾；输入起止 guard 与 padding 组合必须完整保留。

## 实际 dispatcher 和直接 helper 建议

另用独立插桩构建核对 `conv_sve_rowseven` 的实际进入，而不是从数值正确推定分派。

|子矩阵|ow|kh / kw|oh|每配置 case 数|rowseven 预期总进入数|
|---|---|---|---|---:|---:|
|公共 dispatcher|3L、3L+1、6L+1|kh=7..8；kw=1..3|7、8、9、10、11、12、13、14、28|648|936|
|直接 helper 小 kh 回退|1、3L−1、3L+1|kh=1..6；kw=1..3|7、28|432|1080|

计数均包括四个 pad/leading 组合。公共每 case 的 rowseven 数为 floor(oh/7)，九个 oh 的总和为 13；直接入口应由诊断 wrapper 每七行调用一次，两种 oh 的总和为 5。实际计数、worker mask、quad/triple/pair/prefix 尾部进入计数均应打印并按真实实现核对；4 线程配置必须观察到全部四 worker，不能凭理论分派填写。直接矩阵须保持每行全局目的 stride，不可将 helper 七行块误当紧凑尾缓冲区。

上述完整/dispatcher/direct 三部分建议每配置 6728 case，六配置合计 40368 case；这是未来设计预算，当前通过数为未知。实际生成诊断时若调整集合，必须同步保存真实预期计数与原因。

## 另行设计并单列的路径

- 无效尺寸：kh/kw 的 0 和负值、kernel 超过输入、INT_MIN 输入与 INT_MAX 输入配负 kernel 的早退，使用小型有效哨兵对象检查不写 output；不构造不可分配的大 buffer。单列计数，不混入上述 40368。
- 非 SVE：保留生产源码身份，通过单独诊断构建/入口控制屏蔽 SVE 能力，保存诊断差异、实际命中及 guard 结果。编译器和运行平台须真实支持该流程；未做之前不能标已覆盖。
- 生产无插桩汇编：同源、实际 GCC10.3.1 与原 flags；分别审查六个起始、共享、六个收尾、尾列、小 kh 回退、公共分派和所有阶段转换。区分 acc spill 与 ABI 保存，核对 FMA 为零，不能只数共享段。

诊断通过也不构成绩效结论。未来性能实验需根代理另行决定并使用同组前后 C6、原 benchmark 和全部独立套件；本准备任务不建立任何性能 job。
