# T8-paneloutline：独立保留 panel_sums 调用边界

2026-09-12 从 `.runs/trsm/T7-diagpanel/source/` 原样复制候选。共同测量对照由主 Agent 建立为 T7-control11；本候选与 T8-svepanel16 独立，不合并两种策略。此准备工作仅改变候选 `trsm.c` 的 `panel_sums` 声明：在定义 `__GNUC__`、支持 GNU 属性的编译器上，用 `static` 加 `__attribute__((noinline))` 替代 `static inline`；其他编译器保留原 `static inline`，以维持可编译性。Clang 同样定义 `__GNUC__` 并支持此属性，因此也会选择 noinline 分支；当前测量目标为 GCC 12.3.1。

## 单一可检验假设

将既有 NEON 4×8 `panel_sums` 从调用者中独立出来，可能减少 GCC12 下调用者循环中的寄存器压力或重复代码体积。这个辅助函数同时服务于小工作集 `solve_panel` 和大工作集中的紧凑对角面板；收益或退化可能影响两条路径。函数运算、参数、所有调用点和其他函数均不改，递增 k 累加顺序及 FMA 保持原样。

代价包括每个完整四行块的函数调用/返回、ABI 要求的寄存器保存与恢复，以及跨函数优化机会减少。较短点积可能因这些固定成本退化。noinline 不等于禁止其他 GCC 跨过程优化或函数克隆，不保证寄存器使用或代码体积一定下降，也不保证提速；目标生成汇编和同环境测量才是依据。

KB=256、CT=64、64 MiB 算法预算、SVE16 更新、运行时分派、尾部、分配失败回退、官方 benchmark、runner、README 和兼容头保持复制时内容。64 MiB 仍为算法调优预算，不作硬件缓存容量声明。

## 目标节点验证要求

在调度分配的鲲鹏计算节点，与 T7-control11 使用相同 KML25.1、GCC12.3.1、编译选项、38线程、单 NUMA 分配和绑定、TEST_RUNS=3。先检查实际目标汇编中的 panel_sums 调用边界及保存/恢复成本，并完成正常路径、padding、尾部、分配失败和非SVE回退正确性检查；保持官方容差1e-12。随后交错运行三个独立完整官方套件，逐用例保留全部耗时、正确性和环境，比较中位数及波动后再决定是否晋级。KML25.1结果不能写成指定KML25.2.0复验，不与OpenBLAS/GCC10样本混算策略收益。
