# C36-qmajor：四行共享双列循环按列推进

父版本与源码来源均为 **C26-row4loads**（正式 C6 源方案）。准备前已核对原共享中段：它按向量位置 n=0..3 推进，每个 aN/bN/cN/dN 的 ik 与 ik+1 两次更新相邻，**尚不是 q-major**，因此本候选不是重复创建既有排列。

单一假设：先为全部十六个累加器完成 ik 列，再为全部十六个累加器完成 ik+1 列，增加源码中同一累加器相邻两次加法之间可安排的独立工作。GCC 可能重新排回原形态，甚至生成完全相同的指令；也可能因系数、输入或乘积的生存期变化产生更差调度。**没有 C36 目标汇编、正确性或性能结果，不能提前称为提速。**

## 具体范围

只重排 `source/conv2d.c` 中 `conv_sve_rowquad` 的 `t=3..kh-1` 共享中段、现有双列循环体。循环条件和 ik+=2 步进原样保留，八个系数声明 `ak0/ak1/bk0/bk1/ck0/ck1/dk0/dk1` 及其表达式、顺序保持不变。

第一阶段依次加载原 v0/v1/v2/v3；每个 vN 更新 aN/bN/cN/dN 的 ik 项。第二阶段依次加载原 x0/x1/x2/x3；每个 xN 更新这四个累加器的 ik+1 项。**原八条输入加载语句和三十二条乘加更新语句逐条保留，只调整声明/更新的排列**，每轮仍有八次输入加载、八次系数广播、32 次独立乘法和32次加法。末 x3 仍只读取 `p+3*lanes+1` 的合法窗口，不读额外 v4。

没有 lane intrinsic、FMA、asm、prefetch、新循环、分派或尺寸特判。不含 C35 的预取。共享中段的单列余数、其它六个首尾阶段、quad/triple/pair/prefix/tail、OMP 调度和非 SVE 路径保持原文；benchmark、run.sh、源码 README、flags 和容差不变。

## 浮点顺序

对任意输出行 r 与向量位置 N，每次双列迭代仍为 `acc = add(acc,mul(vN,kr[ik]))`，随后 `acc = add(acc,mul(xN,kr[ik+1]))`。两次之间仅插入其它独立输出的计算，不拆分累加器、不新建部分和、不横向求和，也不重关联。外层 t 递增，四输出使用 kernel 行 t/t−1/t−2/t−3；每个输出自身仍严格按 kernel 行和列递增顺序累加。原单列余数接在所有完整双列之后。

输入和权重只读，输出在块末写入；在原有效缓冲区及 restrict 前提下，移动这些读取不会与同块输出写入产生依赖。源码保持数值顺序不等同于已通过目标逐位验证。

## 地址与整数边界

- 已有 quad 满块条件 `ow-i>=4*lanes` 保证 `i+4*lanes<=ow`。新排列未形成任何新的地址表达式，SVE 向量长度继续由 `svcntw()` 决定。
- 双列条件 `ik<kw-1` 只在 kw>0 的合法调用中使用，成立时 ik+1<kw，且 ik+2<=kw，步进不新增 int 溢出。kw=1 跳过双列循环，奇数 kw 的最后一列由原余数路径完成。
- x3 的最大读取列为 `i+ik+4*lanes<=ow+kw-2=inputWidth-1`；其他七个窗口的末列不更大。四个 v 窗口和四个 x 窗口与父版本完全相同。
- 中段 t 始终为3..kh−1，预先的 kh<4 回退不变。四行组由剩余输出行数>=4保证，既有最大输入行 j+kh+2 合法；中段新排列只读原 j+t 行，不扩大行范围。
- 输出行指针、全局 ow 步长、分组数和静态 OMP 分配全部未改，仍每个输出只由一个线程写入。原数组容量前提不变。
